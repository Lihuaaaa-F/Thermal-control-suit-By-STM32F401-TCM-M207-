六、真机发现与处置：交付固件上急停解除不了（已修，提交 ffd8378）
第一次做第五节时，ack 没有解除：回复 "ack: alarm=0x0004 armed=0 state=3"，状态不变。
  根因：ESP32 的 safety_ack_latched() 清急停锁存要求"体温、模块、水温三个源全部恢复"，control_poll() 退出 SAFE
  也要求体温源恢复。这台设备体温探头从开机起就不在（未布防），体温源永远不会恢复。锁存存在 NVS，重启也出不来。
  以前没发现：R1 与 U 线在真机上验证"急停 → 确认解除"用的是现场档固件，可以注入假体温。
  修法（按"其余按默认完成"的授权，已列入待决清单）：未布防时体温源不计入解除条件；已布防后探头丢了不受影响。
  验证：主机用例 N1–N5 修前 7 条断言失败、修后全过；变异 M27–M30 全部被抓住；真机结果见下。
  重启后锁存恢复（顺带验了 F05 的前半）：status → fan=100% alarm=0x0004 state=3 latch=0x08 up=35s
  ack（修复后的固件）→ ack: alarm=0x0000 armed=0 state=3 → status：fan=0% alarm=0x0000 state=0 latch=0x00
  再走一遍完整的急停 → 解除：结果即第五节。

  2. 屏幕上点横幅解除：同样需要触摸，没有做；它和 ESP32 控制台 ack 是同一个函数（本次修的）。
  3. 网页（手机连热点）、二维码扫码、断电冷启动、改参后掉电保持。
  4. 分区表删掉 www / user 之后在设备上的核对：烧录写入的分区表就是新的那一份（应用能正常启动并工作），
     还没有把设备上的分区表读回来逐字节比对。
