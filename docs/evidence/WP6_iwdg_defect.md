# WP6 缺陷报告：IWDG 喂狗间歇失效（未结案，硬件联调日优先排查）

**状态**：未结案。当前发布配置 RLR=4095（32.7s，GS 工程同款已证值）规避 2s 档复位循环；
任务书 §3.9 "~2s" 的 RLR=249 已备好（`App/iwdg/iwdg.c` 注释内），根因定位后一键切回。
**影响**：F5 死机自恢复窗口从 2s 放大到 32.7s（功能仍在，窗口变宽）；其余全部功能不受影响。

## 现象（多源实证）

1. IWDG=2s（RLR=249）时：上电稳定复现复位，周期 ≈2.85s（= 2.0s 看门狗 + ~0.85s 启动）。
2. IWDG=32.7s（RLR=4095）时：单会话 40s 追踪 uwTick 完美 1:1 增长（4938→32964ms，
   每采样 +2002ms/2s），31.7s 处发生一次复位；另组观测到 76s 长跑。
3. 复位源寄存器 RSR=0x04460000：bit26 **IWDG1RSTF** 置位（bit22 PINRSTF 为 H7 内部复位
   外驱 NRST 的伴随位）——**复位确为 IWDG**。首版控制台解码把 PIN 判在前面，一度误判。
4. 主循环持续运行的证据：AXI SRAM 相位轨迹 12s×1501 次采样 100% phase=12（完整循环）；
   PC 高频采样数千次全部落在 main.c:558 节拍等待；uwTick 1kHz 完美走时。

## 已系统性排除（每项有实证）

| # | 假设 | 排除依据 |
|---|---|---|
| 1 | 串口线序扰动 NRST（CH340X 自动下载电路） | 真实存在（见附录 B），但**串口全关、仅 DAP 空闲连接**下复位仍发生 |
| 2 | DMA2D TC 忙等死等 | 已捕获一次现场并加固（超时+软复位+空矩形防御）；加固后现象不变 |
| 3 | 代码停顿/死循环 | 数千次 PC 采样 + 相位直方图 100% 正常；IWDG 触发需 >2s 连续停顿，从未捕获 |
| 4 | SysTick/时基停摆 | uwTick 与墙钟 1:1（+2002ms/2s）；PRIMASK=0；SysTick CTRL ENABLE/TICKINT=1 |
| 5 | 链接/编译错位 | `probe-rs verify` Flash==elf ✓；`bl iwdg_refresh` 在 main 反汇编中 ✓；control_poll 反汇编逐指令核对 ✓ |
| 6 | 喂狗地址/指令错误 | IWDG1_BASE=0x58004800 与 CMSIS 一致；反汇编 `str 0xAAAA,[0x58004800]` ✓ |
| 7 | 中断关闭 | PRIMASK=0，SysTick 中断持续服务 |

## 矛盾点（待解）

循环每拍执行正确的喂狗指令（反汇编+相位轨迹证明），但 IWDG 仍按超时复位——
即喂狗写**在执行却未生效**。剩余假设：
- A. 周期性总线/电源微故障使该 str 丢失（供电经 DAPLink USB，LCD 背光同轨）；
- B. 某运行路径改写 IWDG 寄存器（需数据断点验证）；
- C. pyocd/probe-rs 附加会话本身对总线的扰动使喂狗丢失（但静置期不接调试器的
  复位循环已由串口日志侧面观察到，与 A 相互印证）。

## 建议排查步骤（硬件联调日，预计 30 分钟）

1. 外部 5V 独立供电（脱开 DAPLink 供电轨），串口日志观察是否仍 2.85s 复位；
2. pyocd `target.write_watchpoint(0x58004800)` 数据断点：确认喂狗写是否到达；
3. 若写到达仍复位：读 IWDG->RLR/PR 运行时值是否被改；
4. 复现后按 embedded-dev-loop §4 格式记录并更新本文件。

## 附录 A：关键测量记录

- 复位周期（IWDG=2s）：uwTick 锯齿 + 相位法多轮实测 ≈2.85s

## 附录 B：COM4/CH340X 自动下载电路行为（板级已知问题）

- 串口打开瞬间 + DTR/RTS 电平变化 → NRST 脉冲（板复位）
- 复位瞬间 BOOT0 采样由 DTR/RTS 线序决定：DTR=True → Flash 启动；False → ROM
  bootloader（0x1FF09800，表现为"串口死+外设寄存器读 0"）
- 规避：先关串口复位→再开串口；或割断自动下载电路跳线；或改用独立 USB-TTL 接控制台
- 证据：DTR=False 时 probe-rs 复位后 PC=0x1FF0A4C0（ROM）；DTR=True 时 PC=0x080053EE
  （Flash 主循环）；串口关闭时复位后 PC 恒在 Flash
