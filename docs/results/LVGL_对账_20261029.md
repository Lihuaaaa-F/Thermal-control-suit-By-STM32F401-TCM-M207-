## 2. TL-8 判定工具失效（本次最重要的技术发现）→ 已修复并重测

### 2.1 原缺陷

```c
/* 旧 tcs_lvgl.h */
uint32_t bins[40];   /* bin i=[i*25,(i+1)*25)µs（i<39），i=39 = ≥975µs */
```

末桶是**开口桶**（≥975µs 全部堆在一起）。用它计算 P99.9：
- 4ms 处**没有刻度**，结论只可能落在"<1ms"；
- 同函数另有 `over_4000` 计数，实测 benchmark 20.95%、生产 2% 的样本 ≥4ms。

两者矛盾：只要有 2% 样本 ≥4ms，P98 已 ≥4ms，**P99.9 必然 >4ms**。原文档把 TL-8 写成 PASS 属错误判定。

### 2.2 修复（v2）

`tl8_t` 改为：`bins[40]`（0..999µs，25µs/格）+ `tail_ms[64]`（1..63ms，1ms/格）+ `over_64000` + `over_4000`。
判定规则明确化：**10000 样本时 P99.9≤4ms ⇔ over_4000 ≤ 10**。
读取工具：`project_tcs/tools/tl8_read.py`（probe 直读，输出 P50/P90/P99/P99.9/max 与判定）。

### 2.3 重测结果（真机 L3，bin md5 `7c9399a553382633bc48f0a178579950`）

```
samples=10000  done=1
P50=125µs  P90=125µs  P99=13000µs  P99.9=14000µs  max=70361µs
over_4000=202 (2.02%)   over_64000=1
判定：慢于 4ms 样本 202 个，允许上限 10 个 → FAIL
尾部桶：1-2ms 279 个；11-12ms 74 个；12-13ms 72 个；13-14ms 54 个；≥64ms 1 个
```

**真实结论：TL-8 = FAIL（P99.9 ≈ 14ms）。** 原 G4③/G5② 的 PASS 作废。

### 2.4 根因与修复（已编码，待上板复测）

尖峰呈严格 500ms 周期（2.02% ≈ 每 50 个样本 1 次）＝`tui_tick()` 的 500ms 数据刷新。
`lv_label_set_text` 在文本相同时也执行 `lv_realloc` + `lv_obj_invalidate`（已核对 `lv_label.c`
`set_text_internal`），于是 5 个数值标签每 500ms 全部重排重绘，单次 handler 11~14ms。

修复：新增 `ui_lab_set()`——文本相同直接返回，不 realloc 不 invalidate；p0/p1/p2 的刷新全部改走它。
已构建（bin md5 `49e3cb66745598ed7330d9303e649846`），**因调试器故障尚未烧录复测**。

## 5. 找茬记录（1.4；本次新增，G4/G5 各一遍）

### G4 找茬（视觉放大 / 极端输入 / 竞态打断）

1. **视觉放大**：home 18 片 8× 复查（既有）+ 本次 `s00_home.png` 全帧 token 采样——发现并记录了
   "CARD 与 BG 仅差 1 个 565 LSB"（#F2F3F5 vs #EEF1F5），放大后卡面边界主要靠 BORDER 描边区分，
   低对比面板上可能看不清 → 记录为观感风险（PL-4 实拍复核项）。
2. **极端输入**：TL-8 采样器在 ≥975µs 处无刻度 → 结论不可解析（本轮最严重缺陷，已修）。
3. **竞态打断**：调试器块传输与擦写并发时（pyocd 在 1MHz 下 erase/program 中断）→ 得到**半写镜像**
   （0x08000000 起有效、0x08060000 起全 FF），表现为"上电不启动、PC 落在 0x2400000x"。
   教训：**烧录后必须做多点回读校验**，不能只看进度条。
4. 固定动作（容差减半）：TL-8 判定从"直方图末桶"改为"over_4000 与允许数直接比较"，容差口径收紧后可判 FAIL。

### G5 找茬

1. **视觉放大**：`tui_diag` 极端内容页设计时发现——最长参数名/最长单位若超过卡内宽会被裁切，
   已加 `g_diag_stat[1..4]` 宽度断言（待上板取数）。
2. **极端输入**：空字符串 label 走 `lv_label_set_text("")` 时旧实现会 realloc 到 1 字节并 invalidate；
   已由 `ui_lab_set` 的同文短路覆盖。
3. **竞态打断**：500ms 刷新与页面重建竞争——`tui_tick` 在 `s_mask` 在场时不重建（既有保护）；
   本次补测发现刷新本身即是 TL-8 尖峰源（见 §2.4）。
4. 固定动作：居中审计器 42 元素（既有）+ 本轮 token Δ=0 复核。
