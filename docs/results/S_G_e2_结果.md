## 二、给 e3a 的接口（签名与语义）

都在头文件里，主机可测；本批次只提供取值与判定，不报警、不进 SAFE。

**M207（`esp32/components/tcs_m207/include/m207_service.h`）**

```c
typedef struct {
    uint16_t errstat;      /* TCx:TCERRORSTATUS 原值（8 位：正常=1 故障=0）；0xFFFF=尚未取到 */
    uint16_t otpstat;      /* TCx:TCOTPSTATUS 原值（极性未在真机核实，只透传）；0xFFFF=尚未取到 */
    uint8_t  fault_mask;   /* = m207_errstat_fault_mask(errstat)；尚未取到时为 0 */
    uint8_t  valid;        /* 1=本通道取到过至少一次 */
    uint32_t age_ms;       /* 距最近一次取到的真实毫秒（掉线后继续增长）；0xFFFFFFFF=从未取到 */
} m207_mod_status_t;
int         m207_module_status(uint8_t ch, m207_mod_status_t *out);  /* 0=ok；-1=通道非法或 out 为空 */
uint8_t     m207_errstat_fault_mask(uint16_t errstat);   /* (~errstat)&0x7F：置位=该位保护触发或锁存 */
const char *m207_fault_bit_name(uint8_t bit);            /* 0 external / 1 over-voltage / 2 over-current /
                                                         * 3 over-temp / 4 sensor-open / 5 load-short / 6 load-open */
void        m207_stats_queue(m207_qstats_t *out);        /* qdrop superseded unexpected save_ok save_rej linedrop txdrop */
uint16_t    m207_stats_unexpected(void);
uint8_t     m207_save_busy(void);                        /* 1=保存序列进行中 */
```

语义要点：
- `fault_mask` 的位义取自厂商帮助文件 `tc_hlp.xml`，没有逐位上机核实。位义是"正常=1"，所以取反映码。
- `TCERRORSTATUS` 含上电锁存位，要模块断电重启才清：`fault_mask != 0` 不等于"此刻有故障"。
- `age_ms` 是真实毫秒。掉线期间不轮询，旧值继续可读但龄一直涨——用它判断新鲜度。
- 轮询是 4 条只读查询排普通队列，每 60s 一次；链路空闲时才排，不挤占写与重发。

**风扇（`esp32/components/tcs_fan/include/fan_service.h`）**

```c
typedef enum { FAN_ACT_UNKNOWN=0, FAN_ACT_OFF, FAN_ACT_ON, FAN_ACT_PWM, FAN_ACT_MISMATCH } fan_act_t;
fan_act_t  fan_get_act(void);              /* 引脚实际状态：LEDC 占空比硬件回读 + 命令 0/100% 时的引脚电平采样 */
const char *fan_act_name(fan_act_t a);
uint32_t   fan_mismatch_count(void);       /* 服务启动后每秒核对一次，回读与命令不符的累计次数 */

typedef struct { uint32_t min_on_ms; float min_delta_c; } fan_weak_cfg_t;       /* 默认 300000 / 0.5 */
typedef struct { uint8_t tec_on_prev; uint32_t on_since_ms; float temp_at_on_c; } fan_weak_ctx_t;
/* 返回 1=可疑：TEC 连续输出 ≥ min_on_ms 而 |水温变化| < min_delta_c。now_ms=0 表示时间基准未建立，不下结论。 */
int fan_weak_check(uint8_t tec_on, float temp_c, uint32_t now_ms,
                   const fan_weak_cfg_t *cfg, fan_weak_ctx_t *c);     /* cfg 可为 NULL */
```

语义要点：
- `fan_get_act()` 能发现的只有 ESP32 这一侧的输出通路故障。中间占空比只核对占空比（引脚在 25kHz 翻转，电平不逐点核对）。
- `fan_weak_check()` 是间接证据，恒温稳态下会误判，用之前必须先定阈值与适用条件。

## 四、风险说明

1. **模块保护状态不能直接接成 SAFE（X04-F-05）。** 真机实录（`docs/evidence/R1e_usercheck_run*.log`）里 TC1 恒回 `TCERRORSTATUS=253`（`fault_mask=0x02`），更早是 239（`0x10`，传感器开路锁存位）；TC2 回 255。这些是锁存位，要模块断电重启才清。把它直接接成"非零即报警 / 进 SAFE"，这台设备一上电就永久停机。e3a 接线前要先定：哪些位算故障、锁存位怎么对待、`TCOTPSTATUS` 的极性（没核实）。
2. **弱校验会误判（M13-F-06）。** 自动模式恒温时 TEC 可能连续输出而水温几乎不动。阈值（5 分钟 / 0.5°C）是我按审查方案定的，没有在真机上标定。
3. **TMP117 的配置写入是第一次上机才会验的代码。** 写入值 0x00A0 与比对掩码按 TI 数据手册 SNOSD2D 定。若实物与手册不符，表现为"体温失联"而不是错误的体温——方向是安全的。
4. **风扇电平回读依赖 GPIO42 的输入缓冲。** 已显式 `gpio_input_enable`，但这个脚没有上机记录（GPIO48 上有 `[FANLB] PASS` 的实录）。上机若 `fan_chk` 报 MISMATCH，先怀疑这里。
5. **M207 服务的结构改得很广，但没有任何真机回归。** 决策逻辑整体从 `m207_service.c` 挪到 `m207_core.c`。抽取本身有 60 万拍的新旧差分对照（0 差异）背书，之后的修都只有主机证据。合并后第一次上机建议复跑 selfloop 九步（`CONFIG_TCS_M207_SELFLOOP=y`，逻辑没动，已确认能编译）并对照 `docs/evidence/R1b_selfloop.log`。
6. **审查对 TMP117 的事实有误。** 原文写"默认转换周期 250ms"。数据手册 SNOSD2D：Table 7-3 配置寄存器出厂复位值 0x0220 = 连续转换 + CONV=100 + AVG=01；Table 7-7 连续转换模式下 CONV=100 在任何 AVG 下都是 1 s。也就是原来 100ms 采样下每个转换结果被读约 10 次，8 点均值窗里只有约 1 个独立转换。实际比审查写的更糟。
7. **上线后多出的线上流量。** 每 60s 4 条状态查询（只读）；每秒有一拍不读温度而读 TMP117 配置。

## 六、过程里值得知道的

1. **抽取引入过一个偏差，已修（`f2c1677`）。** 第一版环形缓冲用"留空一格"判满，容量只有 15（抽取前是 16）。60 万拍差分没照出来，因为差分桩里的 FreeRTOS 队列也写成了留空一格——两边同错。是给 X03-F-07 写"灌满 16 条队列"的用例时在未修内核上跑出来的。桩改成按计数判满之后重跑差分：仍 0 差异；并且拿修正后的桩去照未修容量的那一版，5 个场景全部报差异。
2. **条件编译的坑踩了两次。** TMP117 内核里"注入关断时恒 0"的读函数放进了 `#if`，交付档编译不过（`3cdb623` 之前修掉）；M207 内核头文件里的条件声明没包含 `sdkconfig.h`，默认档三次构建都是 0 告警，取证档一编就失败（`c9f36bd`）。两次都是主机过了、目标构建才暴露。

4. **源码门禁自己也有过两个缺陷。** 失败信息里引用了源文件中的中文注释，在 cp1252 的管道下打印会抛异常、把真正的失败原因吞掉；"不得出现 ESP_ERROR_CHECK"把注释里提到的那句也算进去。都已修（转 ASCII 再打印；先剥注释再查）。
5. **对账线索的核实结论。** `recon_GC / recon_GD` 里关于本批次的"未修 / 部分已修"结论都与当前代码一致，没有不同意的地方。任务清单里已剔除的四条（M06-F-08、M12-F-06、X02-F-08、M09-F-11）没有重新核实。
