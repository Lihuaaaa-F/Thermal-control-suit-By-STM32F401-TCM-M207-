## 一、#1 离线占位叠字（已修）

- 现象（主控失联/从未连上）：两张水箱卡的 `°C` 压在 `--.-` 的横线上、"设定"行挤成 `°C.-`；
  体温卡同样。
- 根因：建页时数值占位 `--.-` 与单位 `°C` 都在各自初始 x；`paint_values` 在
  `lv->stale` 时**早退**（设计：断链保持旧值、不刷新），单位永远等不到"按数值宽摆放"那一步。
- 修法：`tui_p0.c` 的 `tc_build` / 体温卡建页时按占位宽度先 `place_unit` 一次；
  `tui_p4_mode.c` 的三张温度卡同样处理（模式页断链也能打开，同一潜在缺陷）。
- 验证：交付档离线态帧转储 `U5_离线占位_修复前.png` / `U5_离线占位_修复后.png`；
  `run_all` ALL GREEN；H743 四档矩阵 PASS。
- 说明：横线本身仍在连字符的基线位置（负温度 "-12.3" 的负号也用它）；若要把占位横线单独上移，
  属观感取舍，未改字形。

## 二、#2 急停恢复验证（只验证，未改代码）

结论先行：**在"解除所需的所有源都健康"的前提下，设计上点一次横幅就够**；既有主机用例已覆盖并全绿。
"点好多次才恢复"的三种真实来源都在"这一次点击不该生效"的路径上，另有 1 条 2026-11-25 已修的历史缺陷。

### 2.1 代码口径（两端）

- 屏（H743）`tui.c banner_tap` + `ui_model.c ui_banner_select`：
  - 只有横幅是 **`UI_BN_TAP_ACK`** 时才发确认（cmd 9）：条件是**链路在 + 主控快照的急停位
    `estop_peer=1`**（且执行器状态允许时说"TEC 已停·风扇全速"，否则说"主控已执行急停"）。
  - 其余横幅（主控连接中断、急停尚未送达、急停指令已发出·等待主控确认、通信类自动恢复、
    功能启动失败、版本不匹配）一律 `UI_BN_TAP_HINT`——**点了只出提示，不发确认**。
- 主控（ESP32）`control.c tcs_alarm_ack → safety_ack_latched`：
  - `drop = 锁存 & 已恢复 & ~ESTOP`；`after = 锁存 & ~drop`；
    **`after` 里没有别的锁存、且解除所需源全部恢复**时，急停位同一次确认里一起清（R-07：避免两次 ack）。
  - "解除所需的源"按布防态取：**已布防 = 体温 + 模块 + 水温；未布防 = 模块 + 水温**（体温不计）。
  - 通信类锁存（体温/模块失联、卡死）源持续健康 2 秒自动清；**急停与超温必须人工确认**。
  - 源不健康时 ack 不清任何相关位，屏收到的是"还有报警"——`ui_ack_reason` 逐条给出原因
    （体温传感器仍失联 / 温控模块通信中断 / 水温过高 …）。

### 2.2 三种"点了没反应/像要点很多次"的真实场景

1. **点的是提示型横幅**：链路不在（"主控连接中断/急停尚未送达"）、急停指令还没被主控确认
   （"等待主控确认"）、通信类会自动恢复的报警等——按设计不可点确认。
   实测（本机，当前主控离线）：注入一次横幅点击 → `g_ui_stat` 点击 +1、toast +1、
   **`g_ui_ack_sent_ms` 仍为 0（确认没有发出）**。
2. **解除条件未满足**：源不健康时点确认，主控拒绝并回原因；**等源恢复后下一次点击即可解除**
   （N2/N3/N4 用例：源恢复 + 一次 ack → 解除）。典型：模块刚上电还没在线、已布防但体温探头没接、
   水温还没降下来。
3. **一次点击其实已清掉急停，但另一条横幅还在**（例如"体温传感器未连接"提示）——
   看起来像"没恢复"，再点它是提示型横幅，不会有动作。

### 2.3 历史缺陷（已修，可能是你记忆里的那次）

2026-11-25 交付固件在**未布防 + 无体温探头**的设备上：解除急停要求三个传感器源全部恢复，
而体温源永远不会恢复 → **急停永远解除不了**（锁存还在 NVS，断电重启也出不来）。
已由 N1–N4 用例定位并修复：未布防时体温源不计入解除前置条件；已布防后探头丢失仍必须等探头恢复（N2 守住）。

### 2.5 待主控上电后的端到端复测步骤（不改固件）

1. 正常解除：屏上按急停 → 等横幅变成"急停已触发 · 点击解除" → 点 1 次 → 记录"点击→横幅消失"时间（预期 <1s）。
2. 模块未就绪：模块离线时按急停并点解除 → 应提示"温控模块通信中断"；模块上线后点 1 次解除。

5. 连点：等待期内连点 3 次——不应重复发确认、不应卡死、不应出现"已解除"又闪回。
