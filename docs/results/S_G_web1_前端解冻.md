用户 2026-11-28 指示："完成 ESP32 端之前说要改的网页内容的改动"。对应 r9f 记录的两处"前端冻结"遗留：

## 一、改了什么

### 1. WS `err` 帧不再一律"无法解析"
- 原状：`app.js` 对所有 `err` 帧只弹"设备无法解析上一条指令"；`c=9`（解除）在屏链路断开时
  被主控如实拒（`{"t":"err","code":"link_down",...}`），前端却要等 `ackMs` 超时再弹"设备未确认 解除"，
  两句都不如真实原因贴切。
- 现值：`ERR_TEXT` 按 code 给人话——`link_down` → **"屏链路断开，急停只能在屏上确认"**；
  `bad_set` / `bad_cmd` 也各有人话；未知 code 用设备自带 `msg`。
  `link_down` 到达时**立刻结束在途的 `c=9`**（不再等超时），只留一条原因 toast。

### 2. 报警卡片补 `ALM_SERVICE(64)` 与 `ALM_PROTO(128)`
- 原状：`ALARMS` 只有 1/2/4/8/16/32 六位；64/128 在网页上不可见（屏端已有横幅与确认原因）。
- 现值：
  - `[64, service, 功能启动失败]`：提示位，无确认按钮，footer 标"需断电重启"；
    说明"部分功能不可用（后台服务没能启动）。请断电重启设备。"
  - `[128, proto, 屏幕与主控版本不匹配]`：提示位，无确认按钮，footer 标"升级后恢复"；
    说明"屏幕与主控的协议版本不一致，屏幕收不到数据。请把两端升级到同一版本。"
  - 实现上给 ALARMS 元组加第 6 个字段（未锁存时的 footer 标签），缺省仍是"将自动恢复"。
