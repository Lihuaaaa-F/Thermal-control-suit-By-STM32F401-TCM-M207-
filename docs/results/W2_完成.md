## 2 为什么这样改（官方依据+被否方案）

**cJSON 化**：同文件下行已用 cJSON（ws_on_recv）——上行手拼=同仓双实现漂移源（F6）；统一后转义/数值格式全归官方库。堆策略=官方 `cJSON_PrintBuffered`（预检缓冲防反复扩），树 Delete/串 cJSON_free 全配对（9 处）。
**queue_work**：esp_http_server.h 头注原文（W10 #16 已录）"should rarely be called directly, with an exception of asynchronous send using httpd_queue_work"——推送任务/link 任务非 httpd 线程，投递=官方唯一合法路径。
**reg 代缓存**：册 §3.2 指定"immutable 大对象缓存"官方模式；触发代=on_link_event（def=当前值随任何参数事件可能变）。

被否方案：❌ 给 ws_push_task 直改同步 API httpd_ws_send_frame——同步版需 httpd_req_t 上下文（外部任务无）；❌ 全局互斥锁包 JSON 构造——各栈自建自毁树/串本无共享，唯一共享点（reg 缓存）用 portMUX 足够（锁面最小化=册 §3.3"后者"路线）。

## 5 找茬记录（≥3）

1. **数字格式语义差（诚实化）**：cJSON 输出 `37` vs 旧 `%.1f` 的 `37.0`——JSON 数值等价（Number()/Chart.js 解析无差）；回归口径=语义等价 diff 非逐字节（报告 §3 注记+前端零改动依据）。
2. **queue_work 深度与停服边界（排除+处置）**：httpd 工作队列深度=CONFIG_LWIP_UDP_RECVMDB_SIZE=**6**（sdkconfig:1793，红队 R1 勘正原"20"误记）；500ms 一帧+偶发 pv 占用 ≤2/6；httpd 停止/队列满时 queue_work 返 ESP_FAIL→工作件 free（无泄漏）；极端堆积=帧丢弃（监控流可忍，急停不走 WS 通道=链路 UART，时序无涉）。
3. **reg 缓存首帧竞态（排除）**：gen 读于锁内、构建于锁外、换入再锁内——事件在构建中到达→built_gen 落后→下次调用判失配重建（保守正确，不吐陈帧）。
4. **测试的真实性边界（诚实化）**：PC 单测复刻构造序列而非直编 websocket.c（esp 头依赖）——转义正确性归 cJSON 官方库+我们"字符串必经 AddString"纪律；该纪律由门禁 2（snprintf=0）机器保证。
