### 2b 内存配对审计（Create/Delete/cJSON_free/malloc/free 逐路径）

- ws_status_json：Create→do-while(0) 任一 Add 失败 break→Delete(root)✓；Print 失败 break→Delete✓；成功 free(j)+Delete✓。**全配对**。
- push_pv：同上模式全配对✓。
- ws_registry_json：root/arr 双 Create 后 `!root||!arr` 双 Delete（Delete(NULL) 安全）✓；it Create 失败 break→随 root 释放✓；Print 失败 Delete 后 return✓；成功 Delete(root)→换入→old 延后 free✓（读侧锁内拷贝，无悬垂）。**两处未配对风险**：①`AddItemToObject(root,"list",arr)` 失败(OOM)时 arr 未被 root 接管→Delete(root) 不释放 arr→**泄漏整棵数组**；②Add 失败或成功均可能把缺 t/缺 list 的残树打印成 `{}`/残帧**入缓存并标最新 gen**（空缓存固化）→ R3。
- fds_send：malloc(w)→queue_work!=ESP_OK→free(w)✓；成功侧 ws_tx_work_fn 尾部 free(w)✓。**全路径配对**（含本版 IDF 的 ctrl_sock_semaphore 满返 ESP_FAIL 路径——httpd_main.c L143-175 红队已读实现确认"fail fast 不静默丢件"）。
- 576B 定长工作件：len>576 静默丢帧（注释已声明"超限即丢该帧"）——最坏推算见 §2e，不触发。

### 2c reg 缓存竞态推演（两个反例）

**反例一（坐实，单调用者即可触发）——gen 虚标致陈帧固化：**
代码 websocket.c:193 `s_reg_built_gen = s_reg_gen;` 赋的是**换入时刻**的 gen，而缓存内容快照于 L160 `link_get_registry`+L168 逐条 `link_param_value`（构建开始前）。
时序：t0 httpd 线程（ws_on_open/h_api_registry）miss→快照数据（对应 gen=5）→构建（锁外，50 条+8KB 打印，亚毫秒~毫秒级）；t1 构建期间 link 任务收到参数事件→on_link_event→`s_reg_gen++`→6（数据已新）；t2 httpd 换入：`built_gen=6`（**虚标**，内容是 gen5 数据）。此后所有调用 `built_gen(6)==gen(6)` **命中陈帧**，直到下一次参数事件才重建自愈。制方找茬 3 的"built_gen 落后→判失配重建"描述与代码行为相反（落后的是数据，不是 built_gen）。附带：事件落在构建循环中间时 def 逐条读取还会产生"部分新部分旧"撕裂帧并被同样固化。危害=网页 reg 帧显示旧 def（UI 级、低概率、自愈）。修复=构建前锁内读 gen 到局部 g0，换入时 `s_reg_built_gen = g0`。

**反例二（当前调用面不可达，记录防御缺口）——换入后无锁 memcpy：**
L197 `memcpy(buf, j, len)` 在锁外使用刚换入的 j。若第二个线程同时重建换入并 `cJSON_free(old=j)` 则 use-after-free。核实 esp_http_server 为单工作线程模型，ws_registry_json 两个调用点（ws_on_open/h_api_registry）均在该线程串行执行→**当前不可达**；但代码以"跨线程安全"自居（加锁）而锁未覆盖该读窗口，依赖的隐含前提（所有换入者均在 httpd 单线程）无注释固化。→R6 wont-fix+二期。

### 2d queue_work 语义（IDF v5.5.5 原文核实）

- esp_http_server.h L1770-1783（httpd_ws_send_frame_async 头注）原文含 "should rarely be called directly, with an exception of asynchronous send using httpd_queue_work"——制方引用属实，st/pv 推送（tcs_ws/tcs_link 任务）经 queue_work 投递=官方唯一合法路径，W10#18 修复成立；ws_on_open 内直调 async（httpd 上下文）合法保留 ✓。
- 工作队列深度：**非制方所写"默认 20"**。httpd_main.c L515-521 实现为 `xSemaphoreCreateCounting(CONFIG_LWIP_UDP_RECVMBOX_SIZE,...)`，本项目 esp32/sdkconfig:1793 `CONFIG_LWIP_UDP_RECVMBOX_SIZE=6`（IDF 默认 6，Kconfig range 6-64）→实际深度 6，占用口径 ≤2/6 而非 2/20。结论（非阻塞、满则丢帧可忍）侥幸成立但依据失实→R1。
- queue 满行为：本版 fail fast 返 ESP_FAIL（非制方所写 INVALID_STATE），fds_send `!=ESP_OK→free(w)` 对两种返码均正确配对 ✓。
