**DoD#4① "复杂度反超"独立核验（官方原文取证）**

- 亲读 `/d/Espressif/frameworks/esp-idf-v5.5.5/components/freertos/FreeRTOS-Kernel/include/freertos/message_buffer.h` 第 42-55 行原文：
  *"…assumes there is only one task or interrupt that will write…not safe to have multiple different writers…**If there are to be multiple different writers then the application writer must place each call to a writing API function (such as xMessageBufferSend()) inside a critical section and set the send block time to 0.**"*
- 要点：SPSC 限制**属实**（评估此半句对）；但官方给的多写者处方=**临界区包 Send+阻塞时间置 0**——本项目 comm_init **已有** enter/exit_critical 注入钩子，照官方处方实现**不需要新增"外互斥"组件**。评估判据①"官方件需求清单=2×MessageBuffer+**外互斥**+…"把官方处方里的"临界区"偷换成"新互斥件"，且"2×MessageBuffer 双通道"全由死代码 push_front 派生（破坏 1.4）。
- 最小 GO 形态独立推演（不引入双通道）：单静态 MB（xMessageBufferCreateStatic，容量 8×(253+4)≈2.06KB≈现 2.02KB 静态 RAM 持平）+ 生产端既有临界区钩子内 Send(…,0)（官方原方）+ 满丢老=临界区内先 Receive(…,0) 丢一帧再 Send（≈6 行）+ 消费端 poll_tx=每 100ms 一次 Receive(…,0)（MessageBuffer 保项定界，一次收一帧，节拍语义天然保持）。总增量约 30-40 行注入后端，**与"6 件套"叙事不符**。
  → **证伪（论据高估）→ 发现 F6（一般）**。
