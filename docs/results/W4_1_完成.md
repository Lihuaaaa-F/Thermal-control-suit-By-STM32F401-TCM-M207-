## 2 为什么这样改（官方依据+被否方案）

**官方依据**：SEGGER 官方 RTT（SEGGER_RTT_printf.c）的格式化子集**不支持浮点**，官方文档明示；官方推荐把浮点先 `snprintf` 成串再 `SEGGER_RTT_WriteString`。本修复将浮点/长度修饰符格式化整体交给 C 库 `snprintf`（newlib，工程已带 `-u _printf_float` 链接旗标，CMakeLists L22，m207.c:456 TCADJTEMP 命令拼装已在产线验证此路径），RTT 侧只做字符串写出——职责与官方分工一致。

**被否方案**：
1. ❌ 给自研 printf 补 %f/'l' 分支——W4.2 即将整体 vendor 官方实现（官方同样无 %f），补丁活不过一个版本期且偏离官方语义；
2. ❌ 调用点格式改 `%u` 绕过（F16 处）——依赖 ILP32 巧合（sizeof(long)==sizeof(int)），掩盖"该 printf 不支持 'l'"的事实，且 64 位移植期成雷；snprintf 模式语义无歧义。

## 5 找茬记录（≥3）

1. **F16 坐实（现象→实验→结论=坐实修复）**：审 printf switch 时疑 `'l'` 修饰符无 case——`%lu` 会走 default 吐字面量且不消费 va_arg。实验：harness 主机直链 segger_rtt.c，`SEGGER_RTT_printf(0,"now=%lu ms",1234567ul)` 输出 `|now=%lu ms|` 字面量 → **坐实**；grep 全库 3 处转换点（post.c:184×1、ft5446.c:422×2）全部同模式修复，门禁扩 `%l` 归零。已回标清单 F16。
2. **门禁自伤（流程缺陷=坐实修复）**：取证 harness 初放 project_tcs/tests/ 内，其"修复前形态"代码使 §1c 门禁命令永久返 5≠0——机器门禁被自己的证据打红。结论：harness 属一次性取证证据，迁至 docs/evidence/W4/（tests/ 只放常驻回归件）；**DoD 改写建议（§1b.5 加分项）**：门禁命令应显式声明扫描域=生产源码树，evidence 目录永不入扫描。
3. **MSVC C4295 噪声（排除证据）**：主机编译 segger_rtt.c 报 `acID[16] 数组太小无法包括终止 null`——`"SEGGER RTT\0\0\0\0\0\0"` 恰 16 字节填满数组。对照官方 SEGGER RTT 控制块布局：acID[16] 本就是 16 字节魔数区非 C 字符串，目标侧 GCC -Wall -Wextra 零告警。结论=官方布局固有，非缺陷；harness 编译档位 /W4→/W3 规避（已在 evidence 头注明）。
4. **链接器 RWX warning（排除证据）**：build 全程唯一 warning=`LOAD segment with RWX permissions`，源自 stm32h743xx_flash.ld 内存区布局，先于本 W 存在（G 线构建同现），与本 diff 无关。
