## 2 主动破坏点

### 2a chdir 锚定（三 cwd 直跑实测）

- 仓库根 `python esp32/tools/official_lib_audit.py` → 135/0/0 exit=0；esp32 目录 `python tools/official_lib_audit.py` → 135/0/0 exit=0；project_tcs（1a）同。三处 REPORT 绝对路径输出一致（manifest/report 路径由 `__file__` 推导，L81-83/L183-184，与 cwd 无关；chdir L73-74 管 ROOTS/walk 枚举域）。连续两次绿态 md5 相同（4824c9ce）=输出确定性。**锚定成立**。

### 2b manifest 注释跳过与误伤推演

- 绿态即证 # 行被忽略（清单头 3 行在文件内而 stale=0——若无跳过机制它们就是 3 条 stale）。
- 误伤方向推演（L98-100 `not l.strip().startswith('#')`）：真路径被误写 `#esp32/…` → 该行不进 covered → 对应文件落 missing → **红+点名**（假红，安全）；不存在文件带 # 写入 → 被跳过，不产生 stale 也不产生假覆盖；用 # 隐藏不想审计的文件 → 文件仍在 files 里，必须以无 # 条目覆盖否则 missing 红。**单向安全：# 机制无法制造假绿，只会制造可发现的假红。**

### 2c 竞态/副作用：报告重写互踩

- 读代码：REPORT 以 `open(out,'w')` 直接覆写（L186），**无 tmp+rename 原子替换**；manifest 只读加载（'r'），写仅在 `--update-manifest`。推演：nightly（audit 跑两遍）与手动 run_all 并发时，两进程写窗口重叠可致证据文档交错损坏；门禁判定（exit 码）不依赖写文件成功，open 失败即异常退出非零（fail-safe），损坏的只是证据 md，下次任一跑自愈。
- 观察者效应实测：docs/ 下任何文件增删改变 D 桶计数 → 报告 md5 随仓库文档活动漂移（制方留档 d318c51b → 红队复跑 4824c9ce，差异=本报告文件入 D 桶）。证据文档因此**不可用 hash 锁定**，但核心三元组稳定。→ 微瑕，见发现 2。

### 2d 探针位置敏感性（两条红路径论证）

- 只读推演（不写真文件）：`esp32/main/tmp_probe.c` ∈ ROOTS（esp32\main）→ iter_files 产出 → 不在 covered → **missing（未入清单）**，报告 L108 `未入清单(缺口)` 点名 missing[:10]，L190 `return 1 if (missing or unclassified)` → **exit=1**。
- 1b 已实测另一半：`project_tcs/tmp_probe.c` ∉ ROOTS（project_tcs 根不在四桶）→ 不进 files → 五桶判定链（.c 后缀不中任何 A-E 桶、`f in covered or f in files` 为假）→ **F 未归类** → exit=1 点名。
- 结论：**两条路径对称且都 exit=1 且都点名**，门禁无位置盲区。但册 §6 探针协议只字面规定了一个位置（见 §3 改写建议 1）。

### 2e stale 计数核查

- 绿态报告实测：`- 清单过期(文件已不存在): 0`——SOP 头 3 行入清单后 stale 仍 0，# 跳过机制真实落地（同时反证：若无该机制，绿态报告会显示 stale: 3）。**未被证伪**。
