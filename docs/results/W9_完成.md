## 2 为什么这样改（官方依据+被否方案）

**dependencies.lock 入 git**=ESP-IDF 官方可复现构建机制（组件管理器设计：manifest 表意图、lock 钉精确版本+哈希；官方文档建议 lock 入版本库保证团队/CI 同版）。此前 lock 被 IDF 模板 gitignore 排除=每次拉取可能漂移到 ^3.0.0 范围内新版。
被否方案：❌ manifest 改 `==3.1.1` 精确锁——manifest 语义是兼容意图，钉死版本该由 lock 承担（双层各司其职=官方设计）；❌ CHECKSUMS.json 手工对账——组件管理器已自动校验，人工重复。

**git tree hash 锁（HAL/nayuki）**：无版本号发布的 vendor 快照（HAL 裁剪版无版本宏、nayuki 无 tag），git tree hash 是唯一防篡改可复核锁（`git rev-parse HEAD:<path>` 任一文件变动即变）。

## 5 找茬记录（≥3）

1. **双重忽略陷阱（坐实修复）**：根 .gitignore 与 esp32/.gitignore（IDF 模板）**都**忽略 dependencies.lock——只改根文件不够（check-ignore 实测仍 IGNORED）；逐一用 `git check-ignore -v` 定位到嵌套规则第 5 行才解锁。教训：嵌套 .gitignore 是隐藏锁定破坏者，红队复核必跑 -v。
2. **HAL 版本锚缺失的定性（诚实化）**：Drivers 无 __STM32H7xx_HAL_VERSION 宏（grep 全 Inc 无命中）——不伪造"V1.11.x"推断值；以 CMSIS V1.10.7（同包 Release_Notes 实证）+tree hash 兜底，GAP 注 1 显式挂账（W1 CubeMX 期核对）。
3. **Chart.js v5 ESM-only 风险（前瞻注记）**：4.4.1 锁定后短期无险；v5 若 UMD 消失则 gzip 嵌入链路（EMBED_FILES）断——入升级风险列，防"顺手升 v5"翻车。
4. **manifest 表 vs lock 表职责（防口径混乱）**：清单中 led_strip 行同时写 ^3.0.0（manifest 意图）与 3.1.1（lock 钉版）并注明双层语义——避免后读者误判"不一致"。
