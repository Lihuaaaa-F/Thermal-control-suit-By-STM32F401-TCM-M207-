## 3. 仿真运行的意外收获——抓到一个生产级集成缺口

仿真让 M207 实际水温第一次"真的在变"，随即暴露：**`m207_last_temp()` 从未被同步进 `g_tcs.tc1/tc2_act`**——正式版即使 M207 在线，屏/网页水温也恒 0，且 **>48°C 过热硬保护实际失效**（保护判据读的正是 g_tcs.tc1_act）。已修：main 主循环每拍同步。这是"能做尽做"仿真路线价值的直接证明（H11：板上三件套最终裁判）。

**另一个真实事件**：验证期间 M207 应答因主机 SWD 高频探测拖慢主循环而 5 次超时→**布防 FMEA 正确触发 SAFE**（TEC 停/风扇开/报警待确认，UI 渲染完全正确）——本身就是一次计划外的 G2 演练；probe 停止后恢复+ack 回 COOL。

## 4. 调试方法学记录（本 WP 踩坑）

- 工具 heredoc 的 `\\n` 会被链路提前吞成真实换行 → C 字符串断串（反复踩）；后续一律 Write 工具整文件写或 chr(92) 构造。
- probe-rs 单字 RAM 读在高总线负载下不可靠（返回 0/FFFF 旧值）——**判定一律以固件自打 stat/RTT 为准**，探针直读仅当参考。

## 5. 遗留与依赖（G1/G2 门禁余量）

- 硬件到位后仅剩"替换验证"：真 M207 跑同套用例（轮询/回读/重发/拔线）、真 TMP117 走失联链、飞线后 H743↔ESP32 联调（U1/U2/U4）。
- 触摸注入验证了 tap 路径（页面切换/参数步进）；**长按连发**为按住时序行为，注入单 tap 无法覆盖，留真机手指实测（录屏并入验收）。
- 体温失联后卡片保持末值 38.1（横幅已提示失联）；是否改"--.-"显示记待决。
