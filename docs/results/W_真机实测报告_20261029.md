## 六、教训（入 methodology）

1. **动板前先读后写**：本会话应先只读板上状态（环/符号扫描），确认基线健康再决定是否刷——我直接刷写是流程错误（尽管做了备份）。
2. **IWDG 固件 + 频繁 halt 调试互斥**：探针每次操作 halt 0.3-0.5s，密集操作可越过 2s 喂狗窗口；作业规程=单次操作后静默 ≥3s、批量读用单会话工具、不在喂狗关键窗口做长会话。
3. **DAPLink HID 链路劣化后的读数据不可信**（同地址两次读不同=必须判读失败而非采信）；出现 Command ID mismatch 连续 2 次即应停手请用户拔插。
4. 备份与恢复必须**逐块 verify** 到 PASS 才算完成；"Finished"回显在链路劣化时不可信。

## 九、2026-10-30 深夜：板间通信方案定案 + 受控激励实验（单线卡点坐实）

### 9.1 STM32↔ESP32 板间通信：方案裁定（用户问"最好的方案"）

| 候选 | 评估 | 结论 |
|---|---|---|
| **UART 230400 + AA55帧/CRC8/ARQ(500ms×3)/去重（现状）** | 负载：下行 0x20@200ms(≈47B/帧,235B/s)+0x21 事件+0x12 SET/ACK；上行 STATUS 60B/s+ACK；合计 <500B/s，对 230400（≈23KB/s）余量 **>40×**；PU 模式 2 线（TX/RX）+共地；ARQ 已实现且 E-10 10%丢包历轮通过（ESP32侧）；延迟=帧时 1.7ms+200ms 快照周期，满足 ≤1s 预算 | ✅ **保持 UART**（工程最优：最少线数、已证协议栈、余量充足、R2 语义已对齐） |
| SPI（主从+CS） | 需 4 线重接+从机 DMA 编程；405KB/s 能力远超需求 → 无收益 | ❌ |
| I2C（ESP 主/H743 从） | 100k/400k、半双工、从机实现复杂；已有 I2C1/I2C4 占用 | ❌ |
| CAN | 收发器成本+协议栈开销，本项目 2 节点无必要 | ❌ |
| 提高 UART 到 921600/1M | 无需求；线长/EMI 风险↑ | ❌（若未来负载涨按 4 倍档再评） |

**裁定：UART@230400+ARQ 即最优方案，不上其它总线；当前唯一缺口=物理线。**

### 9.2 受控激励实验（终结此前反复）
- ESP32 增 `ltx` 命令（UART1 连发 **100×0x55** 特征码）；H743 侧采样窗初版在 ltx 前已被启动噪声耗尽（**实验作废**），改用帧头捕获：遇 0xAA 起抓 32 字节。
- **结果**：6s 内 H743 收到 ~2400 字节（`stat` 新增 `lrx=` 计数：lrx=2440/snap=0），**0xAA 从未出现**；结合全 0x00 流与悬空态签名 → **PA3 上的流=悬空噪声/低电平噪声，ESP32 TX 真实帧未到达**。物理方向 ESP32→H743 不通（H743→ESP32 的 #3 线正常）。
- 已同时排除：波特率（双方 230400，BRR=0x209@120MHz 验算）、AF（PA3 AF7 ✓）、RXNEIE（自愈后=1 ✓）、CRC/协议（两端 proto.c 逐字同源）、组件环（回调注入）。

### 9.3 交付给用户的动作（1 根线）
1. 断电，用**通断档**量 **ESP32 GPIO17 排针 ↔ H743 PA3 焊盘/排针**（不是量"排针有电"——要量两点之间导通），同时确认共地。
2. 若 PA3 侧不可达/接触不良：可把线接 **H743 PD6**（USART2_RX 合法备选），告知后我以 `-DLINK_RX_PD6` 重编重刷（已在代码中预留编译开关，改变量为 0 行手改）。
3. 线通后我立即执行验收脚本：ESP32 `ltx`（0x55 应逐字节出现在 H743 诊断）→ 屏改 tc 设定 → 0x12→ESP32→M207 verify OK→ACK→0x20 快照回灌 → 屏显示新设定与 M207 实际温度（一致性+实时性≤500ms）。

### 9.4 本夜新增常驻诊断面（已清理临时打印，保留正式诊断）
- H743 `stat` 增 `lrx=<RX字节总量> snap=<快照帧数>`：lrx 涨而 snap=0 ⇒ 方向通但解析失败；lrx≈0 ⇒ 物理不通。**屏链自检的标准判据。**
- ESP32 `ltx` 命令（help 在案）：屏链物理自检激励源。
- H743 `-DLINK_RX_PD6` 编译开关：RX 备选映射。
