## 1. 系统架构

```
                     ┌────────────────────────────────────────────┐
   M207 温控模块 ◀──▶ │ STM32H743IIT6（地面站板=主控）               │
   USART3 57600       │  ┌──────────────────────────────────────┐  │      手机
   TMP117 体温 ◀──I2C─│  │ 驱动层: ltdc/ft5446/uart/i2c/eeprom  │  │   ┌─────────┐
   风扇 ◀─────────────│  │    ⇅ 单向依赖                         │  │   │ WiFi STA│
   ESP32-S3 ◀─UART2───│  │ 服务层: param_registry(唯一数据源)    │  │   │  ↓ HTTP │
   (PD5/PA3 飞线)     │  │          m207/tmp117/control/post    │  │◀──│  ↓ WS   │
   7" 1024×600 ◀─LTDC─│  │    ⇅ 单向依赖                         │  │   │ 手机网页 │
   FT5446 触摸 ◀──────│  │ 视图层: tcs_ui/console/link(帧收发)   │  │   └─────────┘
                      │  └──────────────────────────────────────┘  │
                      │  ESP32-S3 = 纯桥 + SoftAP + Web 服务器      │
                      └────────────────────────────────────────────┘
```

- **注册表 = 唯一数据源**：屏/网页/CLI 全部视图由注册表生成；id 永久分配永不复用不改义；消息只加不改载荷。
- **三层依赖单向**：驱动 ← 服务 ← 视图；服务层（registry/m207/tmp117/control/post）零 HAL 依赖、PC 单测直接编译；板级副作用经 hooks 注入。
- **ISR 只置标志/单字节入环**，一切发送在主循环（三处唯一 HAL_UART_Transmit 消费点）。
- **DMA2D 永久弃用**（+32px/行异常、挂死总线、小搬运高开销三重实证）。复活必测三条：①逐行 R2M 步进 ②总线竞争 ③小搬运开销。
- **乒乓双缓冲**：CFBAR 翻页零拷贝；同步（整帧 memcpy）仅允许"切页/弹窗/按住沿(H1)/boot"四类整页事件——`gfx_sync_buffers` 方向=新帧→旧帧缓冲（H1 修正，原实现反拷贝）。
- **扩展成本表**：加参数=注册表 1 行（+映射表 1 行）；加外设=三函数模板；加页面=页表项+帧函数；OTA 通路已留（ESP32 双分区+网络 OTA）。

- **0x08 三态语义（H6 起）**：0=auto（POST 过且数据源健康→布防；**ESP32 主控侧**没有 H743 的六项 POST 电池，"POST 过"指上电参数镜像校验通过——NVS 镜像可读、没有记录因类型 / 持久化标志 / 数值不符被拒、body_cold<body_hot，或为首次上电；镜像损坏后要等一次成功落盘才重新满足，见 S 线 M09-F-06）；1=强制布防（FMEA 恒开）；2=强制不布防（安静，未接线/演示）。旧 0/1 值兼容。
- **0x09 / 0x0A（2026-11-26，m1"模式"页，用户定的新功能）**：两路 TEC（界面叫 TEC1 / TEC2）的手动输出，0 = 暂停 / 1 = 制冷 / 2 = 制热；上电一律暂停（不持久化）。只在手动模式、且不在安全态时可写——不在手动模式 / 安全态 / 取值不是 0~2 → 拒绝（`param_set` 返回 -3 / -4 / -5）。输出映射在 `esp32/components/tcs_core/control_manual.c`：制冷 = TCADJTEMP 15.0 + TCSW=1，制热 = TCADJTEMP 45.0 + TCSW=1，暂停 = TCSW=0（目标温度是固定值，界面不显示）。进安全态 / 急停 / 断链急停 / 切到自动 → 两路置回暂停，确认解除后不自己恢复输出（用户再点，或切到自动）。风扇联动：任一路制冷 / 制热 → 风扇开；两路都暂停 → 恢复联动之前用户的选择。
- 约束：body_cold < body_hot（写任一侧校验另一侧，违反拒写）。
- EEPROM v2 布局：0xA6 magic / ver=2 / count / 8B 记录×N / CRC8@0xF8；自测字节 0xF6（写后必须还原）。
- 只读快照 g_tcs：tc1_act/tc2_act/body_temp/tec1/tec2/fan/mode/alarm/m207_online/body_sensor_ok/esp_link_ok/fw_ver(0x010100=v1.1.0)。

## 2.6 参数所有权矩阵（v1.2，WP-P1 定案）

| 参数类别 | 唯一真值 | H743/ESP32 注册表角色 | 掉电行为 | 双主禁令 |
|---|---|---|---|---|
| 0x01~0x08 业务参数 | H743 EEPROM（R5 后=ESP32 NVS） | 持有+持久 | 读本地 | — |
| 0x100~0x12F M207 可设参数 | **M207 模块 EEPROM**（`!` 后） | **缓存镜像+透传**：上电读回填表，修改=下发+50ms 读回校验，不落本地持久 | **从模块读回**（本地不存） | 禁止双主：本地改≠生效，以读回为准 |
| 0x130+ 只读遥测 | M207 模块 | 周期轮询缓存 | 重新轮询 | — |
| tc1/tc2_set | 本地（业务层） | 持有；变更经映射下发 `TCx:TCADJTEMP` | 本地持久 | M207 侧 ADJTEMP 为执行器设定值，非真值 |

- 写路径（R5 实现口径）：网页/CLI 写 0x100+ → 注册表 clamp（H10 值域）→ 50ms 节流队列下发 `MOD:PARAM=v` → 等 50ms → `MOD:PARAM?` 读回 → |回读-下发|<容差 → 更新缓存镜像；失败重发 1 次后标 NAK（UI 提示，不回滚本地缓存以外的任何状态）。
- `!` 保存=用户显式动作（网页"保存到模块"按钮），**保存语义提示**：生效 vs 掉电保持差异在 UI 文案明示。

## 3. 安全控制（control.c，安全常量硬编码不进参数表）

- 制热目标 45.0°C / 制冷目标 15.0°C / 过热硬阈值 48°C（任意模式自动置 ALM_OVERTEMP，不受布防影响）。
- 自动模式迁移：IDLE→(>hot+hyst)→COOL(TC1=15+风扇开)；COOL→(<hot−hyst)→IDLE；IDLE→(<cold−hyst)→HEAT(TC1=45+风扇开)；HEAT→(>cold+hyst)→IDLE。
- **布防三态机（post.c，H6）**：UNARMED_ABSENT ⇄ ARMED_ONLINE ⇄ LOST_ALARM。ARMED→LOST=数据源失联沿（SAFE+报警）；LOST→ARMED=人工清报警 且 连续 10 次健康采样（上线补入）。
- **合理性滤波（H6.7）**：体温样本 25~45°C 且 |Δ|≤2°C/s（违者按通信错误计入健康计数）；M207 回读 |Δ|>10°C/s 判不可信→按失联路径。
- SAFE：TEC 双停 + 风扇强制开 + 报警位；退出=双源恢复 + 人工确认（ack）。
- 急停（屏弹窗/网页二次确认/KEY0/CLI 同一入口）：TCSW 双停 + 风扇全开 + mode=手动 + ALM_ESTOP，自持需 ack。
- 未布防：传感器类异常只记状态沿，不横幅不进 SAFE（安静）；过热/急停不受布防影响。

## 4. POST 上电自检（post.c，H6）

六项：①TMP117 Device ID==0x0117 ②M207 一拍内首联（宽限 2.5s）③EEPROM 镜像 CRC ④参数表自洽（序列化 CRC+范围）⑤屏+触就绪 ⑥版本/协议/注册表非空。
- 角标 (128,0,640,40) 16px，✓绿(0x16A34A)/✗黄(0x92400E)，3s 淡出；`post badge [ms]` 重显。
- 结论进布防 auto 判据；结果如实显示（触屏 IC 硬件离线→✗，不粉饰）。

## 5. 链路协议（H743↔ESP32，protocol/tcs_proto.h 唯一源）

- 帧层 AA 55|Len|Payload|CRC8；ARQ 500ms×3。消息：0x10 STATUS(19B,500ms)/0x11 PARAM（主控→屏的权威镜像）/0x12 SET_PARAM（屏写参数，等 ACK）/0x13 GET_REGISTRY/0x14 REGISTRY_ENTRY/0x15 CMD/0x20 SNAPSHOT(40B,200ms)/0x21 DELTA(位图增量)/0x22 INFO(设备信息，UTF-8 "key=value" 行)/0x90 ACK。
- 方向（2026-11-25，R5-01）：Payload[0] 的 bit6 是方向位——1 = 发送方 ESP32（主控），0 = 发送方 H743（屏）。方向表：仅 H743 发 0x10 / 0x12 / 0x14；仅 ESP32 发 0x11 / 0x13 / 0x20 / 0x21 / 0x22；0x15 / 0x90 双向。两端 comm 层在收帧的任何处理（ACK、去重、交付、判活）之前，按方向位丢弃本端发出的帧的回送。两端固件必须成对更新。完整说明在 `protocol/tcs_proto.h` 的「方向」一节；方向表与两端源码收发分支是否一致由 `python tools/proto_sync.py --check` 核对。
- **2026-11-26（m1"模式"页）TCS_PROTO_VER 1 → 2**：0x20 快照末尾追加 9 字节——`tec_dir`（1B：低半字节第一路、高半字节第二路；0 暂停 / 1 制冷 / 2 制热 / 3 通道开着但不是"模式"页设的）、`tec1_v`（i16，0.01 V，制热为负）、`tec1_i`（u16，0.01 A）、`tec2_v`、`tec2_i`；长度 40B → 49B。0x21 增量 mask 的高 8 位新增 `0x0100` 输出方向（1B）、`0x0200` 电学量（8B），字段排在低 8 位的字段之后。电压 / 电流的"未知"值 0x8000 / 0xFFFF（没取到、数据龄超过 3 秒、模块不认 `TCx:TCACTVOL` / `TCx:TCACTCUR`）。两端必须成对更新；屏端 POST 的 VER 自检项随版本号同改；网页端状态帧（st 帧）不变。字节向量的三处对照：`esp32/tests/test_tcs_proto.c`、`project_tcs/tests/test_proto_m1.c`、`project_tcs/tools/proto_ref.py` 的 selftest。
- **2026-11-26（S 线 i3，P1-09 / X03-F-08 收口）TCS_PROTO_VER 2 → 3**：0x20 快照末尾再追加 3 字节——`tec_cmd`（命令意图：bit0 = TEC1、bit1 = TEC2）、`tec_act`（模块回显：M207 服务回 `TCSW?` 时写；模块离线期是旧值）、`tec_known`（开关状态是否可信：位为 1 = 模块在线、该路可信；0 = 未知）；长度 49B → 52B。前面的 `tec1` / `tec2` 是命令与回显混用的旧字段，原样保留给旧消费者。**屏端规则：`tec_known` 位是 0 的那一路显示"未知"，不得显示"运行 / 停止"，模式页也不得显示"暂停"**——主控在而 M207 离线时，主控手里只有命令意图，执行器实际在做什么无从得知；同理这一路的输出方向（`tec_dir`）主控报"暂停"只是"没有可信的方向"，屏以 `tec_known` 为准。0x21 增量不带这 3 个量（全量快照 200ms 一帧）。两端必须成对更新；屏端 POST 的 VER 自检项随版本号同改；网页端状态帧不变。字节向量的三处对照同上一条。
- **裁决记录（用户 2026-11-26）：屏链路断开等于发急停。** 主控自上一帧对端方向的合法帧起满 3000 ms → 走与急停命令同一条路径（两路 TEC 全停、风扇全开、锁存、要确认才解除），日志写明原因（`SCREEN LINK LOST`）。只对"上电后连上过、然后断开"生效（上电后屏从没连上过不触发）；已在安全态不重复触发；一次断开只触发一次；链路恢复后保持安全态，直到屏上确认。**取代 2026-11 的旧裁决"断链只报告、不进安全态"。** 代码：`esp32/components/tcs_core/link_loss_guard.[ch]`（纯判定）、`control_service.c`（每个控制节拍问一次）、`tcs_link/comm.c`（方向闸门之后记对端帧时刻）。
- 2026-11-25 勘误：v1.2 初版此处的"0x11 PARAM 变更即推"是屏→主控方向且不等 ACK，已由 0x12 取代（R5 复核 R5-10）。
- 报警位：0x0001 体温 / 0x0002 M207 / 0x0004 急停 / 0x0008 过热 / 0x0010 EEPROM。
- 勘误：STATUS 长度 19B（v2.3 任务书表尾"17B"系算术口径漏加 online+rfu，以字段清单为准）。
- 同步预算：网页↔屏 ≤1s = 500ms STATUS + 500ms 屏扫描（端到端实测留 I1/I5）。

## 6. 网页（ESP32 内嵌，gzip EMBED）

- 注册表驱动参数区（PF_WEB），M207 参数自动进高级区；模式/布防模式为控件特殊渲染（布防三态文案：自动/强制布防/强制不布防）。
- 重连（H2）：指数退避 1,2,4,8,10s 上限；连败 12 次（≈95s）自动整页刷新（清 JS 态；AP 整体离线为物理边界）。
- CSV 导出（H7）：`unix_time_s,body_temp_c`，30min 窗口 2s 采样。
- 触控目标 ≥44px；断连灰罩+倒计时；急停二次确认。
- **热点口令与 NVS（M10-F-06，2026-11-26 增补）**：热点口令是固定值（`TCS-<MAC 后 4 位>` / `12345678`，可用 NVS `tcs` 命名空间的 `ssid` / `pass` 覆盖），**口令非机密**——它只用来把偶然邻近的设备挡在外面，不是访问控制；网页控制台不做鉴权（P1-15 的 token 部分，2026-11-25 产品决定）。NVS **不加密**，参数镜像与热点凭据明文落盘。量产若要加密（NVS 加密 + `nvs_keys` 分区、口令随机化并在屏上显示），需要产线烧录环节配合，列为后续项。在此之前口令不得写进串口日志与证据文档（固件启动日志自 2026-11-26 起打印 `pass=***`）。
