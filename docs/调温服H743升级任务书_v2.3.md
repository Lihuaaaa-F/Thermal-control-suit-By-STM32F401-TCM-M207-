## 1. 项目定义

### 1.1 一句话目标

调温服控制核心迁移至 **STM32H743IIT6 地面站板**：7 寸 1024×600 触摸屏本地显示+触摸调参，ESP32-S3 WiFi 热点 + 网页手机远程调参；M207/TMP117/风扇直连 H743；F401 与 OLED 退役。

### 1.2 系统架构

```
                 ┌──────────────────────────────┐
                 │  7" 1024×600 RGB + FT5446 触摸 │
                 └──────────────┬───────────────┘
                                │ LTDC+SDRAM 双缓冲 / 软件I2C(PD12/13,PH6/7)
   DAPLink ──SWD──┐   ┌────────┴─────────────────┐
  (烧录+RTT)      ├───┤   STM32H743IIT6 主控       ├──USART3(PB10/11)──► M207 温控模块(TEC,双水箱) @57600
   PC ──COM口─CH340───┤  project_tcs 固件          ├──I2C1(PB8/9)─────► TMP117 体温 @0x48
  (USART1 控制台)     │  参数注册表 = 唯一数据源     ├──PB14───────────► 风扇光耦(低有效)
                      └────────┬─────────────────┘
                               │ USART2(PD5/PA3) @230400 + proto/comm 可靠链路
                      ┌────────┴─────────┐
                      │  ESP32-S3 N16R8   ├──GPIO17(TX)/GPIO18(RX) 对接上行
                      │  tcs/esp32 扩展    ├──WiFi AP──► 手机浏览器
                      └──────────────────┘
```

职责：**H743=唯一数据源**（存储/校验/限幅/持久化/联动/安全），**ESP32=纯桥+Web 服务器**（不存业务参数、不做决策），屏与网页皆为视图。退役：F401、12864 OLED、墨水屏方向。

### 3.2 裸机调度与并发模型（铁律）

主循环 10ms 节拍（SysTick 计数分频），**所有参数写操作只在主循环上下文**（触摸轮询/console 解析/链路帧处理均在主循环内完成）；ISR 只做：UART RX 单字节入环形缓冲、置标志。**禁止在中断里调 HAL_UART_Transmit/解析协议/写参数**（GS 工程 §0E 教训已固化在 comm.c 设计里）。主循环时序预算（最坏值，超预算=缺陷）：

| 每节拍工作 | 预算 |
|---|---|
| 触摸轮询(ft5446_read) | 0.3ms |
| m207 状态机 + 行解析 | 0.3ms |
| console RX/解析 | 0.2ms |
| ESP32 链路 RX(comm_rx_feed_byte 循环) | 0.3ms |
| control 评估(500ms 周期) | 0.1ms |
| tcs_ui 脏区重绘 | ≤6ms（局部）/ 全屏 ≤25ms（仅切页时） |
| TMP117 采样(100ms 周期) | 0.2ms |
| 喂狗+合计 | **≤8ms/节拍**（余量 2ms） |

### 3.3 参数注册表（防返工核心 ★）

```c
typedef enum { PF_RW=0x01, PF_SCREEN=0x02, PF_WEB=0x04, PF_PERSIST=0x08, PF_M207=0x10 } param_flags_t;

typedef struct {
    uint16_t    id;          /* 协议/EEPROM 锚点，永不复用永不改义 */
    const char *key;         /* "tc1_set"，CLI/JSON 用 */
    const char *name;        /* UTF-8 中文显示名 */
    const char *unit;        /* "°C" / "" */
    uint8_t     type;        /* 0=f32 1=u8 2=u16 */
    uint8_t     flags;       /* PF_* 组合 */
    float       min, max, step;
    float       value;       /* RAM 当前值 */
    uint8_t     dirty_persist; /* 待写 EEPROM */
    uint8_t     dirty_ui;    /* 待广播(屏+链路) */
} param_desc_t;

param_desc_t *param_find(uint16_t id);            /* O(1) 数组线性即可(≤32项) */
int   param_set(uint16_t id, float v, uint8_t src); /* clamp→相等短路→写→置脏→返回0；越界返回clamp后值经src通道回显 */
float param_get(uint16_t id);
void  param_persist_flush(uint32_t now_ms);        /* 防抖 2s 增量写 EEPROM */
void  param_broadcast(param_desc_t *p);            /* 屏脏区 + TCS_PARAM 链路帧 */
void  param_load_defaults(void);  void param_load_eeprom(void);
```

**参数表 v1（id 永久分配）**：

| id | key | name | 初值 | [min,max]/step | flags |
|---|---|---|---|---|---|
| 0x01 | tc1_set | 贴身水箱设定温度 | 25.0 | [5.0,45.0]/0.1 | RW+SCREEN+WEB+PERSIST+M207 |
| 0x02 | tc2_set | 环境水箱设定温度 | 25.0 | [5.0,45.0]/0.1 | 同上 |
| 0x03 | body_hot | 体温过热阈值 | 37.5 | [36.0,40.0]/0.1 | RW+SCREEN+WEB+PERSIST |
| 0x04 | body_cold | 体温过冷阈值 | 36.5 | [35.0,39.0]/0.1 | RW+SCREEN+WEB+PERSIST |
| 0x05 | hyst | 滞回回差 | 0.2 | [0.1,1.0]/0.1 | RW+SCREEN+WEB+PERSIST |
| 0x06 | mode | 控制模式(0手动/1自动) | 0 | [0,1]/1 | RW+SCREEN+WEB+PERSIST |
| 0x07 | tc_set_confirm | 高温二次确认阈值 | 40.0 | [38.0,45.0]/0.5 | RW+WEB+PERSIST |
| 0x100+ | m207_* | 待文档 | — | — | RW+WEB+PERSIST+M207（**无 SCREEN**，D6） |

约束实现：param_set 内强制 `body_cold < body_hot`（写任一侧时校验另一侧，违反则拒写返回错误）。

**只读状态快照**（tcs_state_t，不入写表）：tc1_act/tc2_act(f32°C)、body_temp(f32)、tec1_on/tec2_on(u8)、fan_on(u8)、mode(u8)、alarm_bits(u16 位定义见 §6.2)、m207_online/u8、body_sensor_ok/u8、esp_link_ok/u8、fw_ver/u32 BCD。

**EEPROM 布局 v2**（AT24C02 256B，扩展自 GS magic+CRC 模式）：

| 地址 | 内容 |
|---|---|
| 0x00 | magic=0xA6 |
| 0x01 | layout_ver=2 |
| 0x02 | count (N≤31) |
| 0x04.. | N×8B 记录 `{id u16le, type u8, rfu u8, value u32le}` |
| 0xF8 | CRC8（覆盖 0x00..0xF7，proto_crc8 复用） |
| 0xF9-0xFF | 保留（自测字节 0xF0 改 0xF6，避开 GS 固件用过的 0xF0，防两固件互踩） |

规则：读回 magic/ver/CRC 任一不符 → 全部默认值 + `[WARN] eeprom cfg invalid`；**EEPROM 离线不阻塞**（沿用 GS 降级设计）。写入策略：param_set 置脏 → 2s 防抖 → 只写变更记录所在 8B 页 + CRC 页。

### 3.4 M207 协议模块（m207.c/h）

```c
void  m207_init(UART_HandleTypeDef *huart);      /* 挂 USART3 @57600 */
void  m207_poll(uint32_t now_ms);                /* 主循环节拍调用，内部状态机 */
int   m207_set_temp(uint8_t ch, float v);        /* 入下发队列，异步 */
int   m207_tec(uint8_t ch, uint8_t on);          /* TCx:TCSW=0/1，异步 */
float m207_last_temp(uint8_t ch);
```

指令集（自 F401 V4.1 源码核实；高级指令等文档）：`TC1/TC2:TCACTTEMP?\r`（查）、`TCx:TCADJTEMP=<f>\r`（设）、`TCx:TCSW=<0/1>\r`（启停）。回复 `TCx:TCACTTEMP=<f>\r`。

**轮询状态机**（替代 F401 的阻塞 HAL_Delay 版本）：

| 状态 | 事件 → 迁移 |
|---|---|
| IDLE | 到达轮询时刻(500ms/通道交替) → 发 `TCACTTEMP?` → WAIT_REPLY，记 deadline=+100ms |
| WAIT_REPLY | 收到完整行 → 解析更新 tcX_act → IDLE（该通道 fail_cnt=0） |
| WAIT_REPLY | 超时 100ms → fail_cnt++ → IDLE |
| IDLE | fail_cnt≥5（≈2.5s×2通道） → 置 m207_online=0 + ALM_M207_LOSS → 进入 RECOVER |
| RECOVER | 每 1s 发一次 `TC1:TCACTTEMP?` 探测；任一成功 → online=1、清报警 → IDLE |

RX 通路：USART3 RX 中断单字节 → 512B 环形缓冲（SPSC，head 仅 ISR 写）→ 主循环取字节拼行（\r 结束，行长上限 64）。**ORE 溢出先清标志再重置接收**（F401 踩坑防御保留）。解析器 `m207_parse_line()` 从 F401 `ProtocolAnalysis` 移植，接口改为 `int m207_parse_line(const char *line, m207_reply_t *out)`（返回模块号 TC1/TC2/参数名/浮点值），**先写 PC 单测再上板**（§5.1）。

写路径确认机制：`m207_set_temp` 下发后，下一轮该通道轮询时回读校验 |实际回读设定−下发值|<0.05，不一致自动重发 1 次，仍不一致 → `[WARN] m207 set NAK ch=1`（不报警横幅，仅日志+网页事件）。

### 3.5 TMP117 模块（tmp117.c/h）

硬件 I2C1（HAL_I2C_Mem_Read，7 位地址 0x48，寄存器 0x00，2B 大端，`raw×0.0078125=°C`）。100ms 采样，滑动均值窗口 8。健康判定：连续 10 次通信错误 → body_sensor_ok=0 + ALM_BODY_SENSOR。恢复：连续 3 次成功 → ok=1（**报警位保持，需人在屏/网页确认清除**，防间歇接触误判恢复）。

### 3.6 联动控制状态机（control.c/h）

每 500ms 评估一次，输入=body_temp 滑均值。**手动模式(0)**：TEC/风扇由 UI/网页直接控制，本状态机旁路——但 §6 安全态优先级高于手动。**自动模式(1)** 迁移表：

| 当前态 | 条件 | 动作 → 次态 |
|---|---|---|
| IDLE | body>body_hot+hyst | TC1 设 15.0(制冷常量) + TCSW=1 + 风扇开 → COOL |
| IDLE | body<body_cold−hyst | TC1 设 45.0(制热常量) + TCSW=1 + 风扇开 → HEAT |
| COOL | body < body_hot−hyst | TCSW=0 + 风扇关 → IDLE |
| HEAT | body > body_cold+hyst | TCSW=0 + 风扇关 → IDLE |
| 任意 | 传感器丢失/M207 失联 | **安全态 SAFE**（TCSW=0 + 风扇开 + ALM） |
| SAFE | 传感器与 M207 双恢复 + 人工确认(屏/网页按键) | 清报警 → IDLE |

TC2 通道维持用户手动设定（原 F401 逻辑：联动只控 TC1 贴身水箱）。滞回算例（默认参数）：>37.7 进制冷、<37.3 退制冷；<36.3 进制热、>36.7 退制热——写进单测向量。

**P1 调参页**（主页点「调参」进入；列表项=注册表 `flags&PF_SCREEN` 自动生成）：

| 控件 | rect | 行为 |
|---|---|---|
| 列表 8 行 | (16,56+i·56,640,48) i=0..7 | 行内：name(32,y) + 当前值右对齐(480,y)；选中行高亮 ACCENT 边框；点选 |
| − 大按钮 | (700,168,140,140) | 步进 −step；**长按 400ms 后每 150ms 连发** |
| + 大按钮 | (884,168,140,140) | 同上 |
| 步进切换 | (700,336,324,56) | 「步进 0.1 / 1.0」切换（0.1↔1.0×10） |
| 范围提示 | (700,408,324,40) | `范围 5.0 ~ 45.0 °C` 灰字 |
| 保存并返回 | (700,544,324,56) | 立即 flush EEPROM + 回主页 |
| 返回 | (16,544,200,56) | 不保存也回（值已是实时生效的，见下） |

**语义：调参即实时生效**（param_set 立即写 RAM 并下发 M207/驱动联动），「保存」仅指 EEPROM 固化——页顶常驻灰字说明。列表项 >8 个时右侧滚动条（上下滑动），M207 高级参数无 SCREEN 位永不出现于此（D6）。

**急停二次确认弹窗**：全屏半透明遮罩 + 「确认急停？TEC 将全部停止，风扇全开」+ [确认](412,300,200,64 红) / [取消](612,300,200,64)。确认 → `tcs_emergency_stop()`：双通道 TCSW=0 + 风扇开 + mode=手动 + ALM_ESTOP + 广播。任何页面顶栏左侧放小急停图标(120,0,80,40) 常驻可达。

触摸去抖 30ms；抬手才触发（touched 1→0 沿判定），长按用按住时长实现；**同一时刻只响应第一个触点**（FT5446 多点忽略）。

### 3.8 控制台（console.c，USART1@115200 经 COM 口）

printf 重定向 UART1 轮询发送（`_write`→HAL_UART_Transmit 超时 10ms，缓冲满丢弃+计数）。日志前缀规范 `[SYSTEM]/[APP]/[SENSOR]/[NET]/[ERROR]/[WARN]`。CLI（行缓冲，\r 或 \n 结尾，20ms 轮询）：

| 命令 | 功能 |
|---|---|
| `ver` | 固件版本/编译时间/参数表版本 |
| `stat` | 全状态快照一行式（含 alarm_bits 十六进制） |
| `p list` | 全参数 `id key value [min,max] flags` |
| `p set <id> <v>` | 等价触摸/网页调参（同一 param_set 路径） |
| `p save` | 立即固化 EEPROM |
| `p defaults` | 恢复默认（需 `p defaults Y` 确认） |
| `mode <0|1>` / `tec <ch> <0|1>` / `fan <0|1>` / `estop` | 控制命令（与 UI 同路径） |
| `m207 send <raw>` | 原始指令透传（调试期专用） |

### 3.9 IWDG / 复位

IWDG ~2s，主循环喂；复位后首行日志打复位源（RCC CSR 解析）；EEPROM 参数恢复，默认 mode=手动、TEC 保持停止（**上电不自动恢复 TEC 运行**，安全默认）。

## 4. ESP32-S3 + 网页详细设计（D:\Espressif\ws\tcs\esp32）

### 4.1 组件结构


### 4.2 H743↔ESP32 链路（跑在 proto 帧层 AA 55|Len|Payload|CRC8 + comm ARQ：500ms 超时×3 重传）

消息号段 0x10-0x16/0x90-0x91（与地面站无人机协议 0x01-0x05/0x81-0x85 无冲突，已核 §12.3-C4）：

| MsgType | 方向/频率 | 载荷（字节级，小端） |
|---|---|---|
| 0x10 TCS_STATUS | H743→ESP，500ms | ver u8, seq u32, tc1_act i16÷10, tc2_act i16÷10, body i16÷10, tec1 u8, tec2 u8, fan u8, mode u8, alarm u16, online u8(位0 M207/位1 传感器/位2 ESP链路), rfu u8 = **17B** |
| 0x11 TCS_PARAM | H743→ESP（变更即推+握手全量） | id u16, type u8, value u32(按 type) |
| 0x12 TCS_SET_PARAM | ESP→H743（ACK 必达） | id u16, type u8, value u32 |
| 0x13 TCS_GET_REGISTRY | ESP→H743 | 无载荷 |
| 0x14 TCS_REGISTRY_ENTRY | H743→ESP×N 条 | id u16, type u8, flags u8, min f32, max f32, step f32, keylen u8, key[k], namelen u8, name[n](UTF-8), unitlen u8, unit[u]（单帧 ≤250B，超长参数条数拆多帧，条目有序号 count u8+idx u8 头） |
| 0x15 TCS_CMD | ESP→H743（ACK 必达） | cmd u8（1=tec1 on 2=tec1 off 3=tec2 on 4=tec2 off 5=fan toggle 6=mode auto 7=mode manual 8=estop 9=alarm_ack） |
| 0x90 TCS_ACK | 双向 | acked_seq u8, acked_mt u8, status u8(0=ok 1=clamp 2=bad_id 3=busy), ret f32（SET_PARAM 回实际写入值） |

版本策略：STATUS.ver 不匹配 → 网页黄条「固件协议 v%d≠网页预期 v%d，功能可能受限」不拒绝服务。心跳：ESP 1s 发 GET_REGISTRY 无意义探测帧改用 0x10 自身即可判链路（comm.link_ok），断链 3s → 网页灰罩。

### 4.3 网页（无构建链单页应用，全部资源 EMBED 进固件——**AP 无外网，禁用任何 CDN**）

文件：`index.html` + `app.js` + `style.css` + `chart.umd.min.js`（本地嵌入）≈ gzip 后 <150KB。

**REST/WS API**：

| 路由 | 方法/帧 | 语义 |
|---|---|---|
| `/` `/app.js` `/style.css` `/chart.umd.min.js` | GET | 静态（gzip EMBED） |
| `/api/status` | GET | 当前 0x10 快照 JSON（HTTP 兜底） |
| `/api/registry` | GET | 注册表 JSON（ESP 缓存自 0x14） |
| `/ws` | WebSocket | 推 `{"t":"st",...}`(500ms)、`{"t":"pv","id":1,"v":30,"src":"touch"}` 参数变更 |
| — | WS 发 | `{"t":"set","id":1,"v":30.5}` → 等对应 `{"t":"pv","src":"web_ack",...}` 回显（ACK status=1 clamp 时弹 toast「已限幅至 45.0」） |
| — | WS 发 | `{"t":"cmd","c":8}` 急停；急停在网页为红色大按钮+二次确认，与屏同一 `tcs_emergency_stop()` |

页面结构（手机竖屏优先，响应式 ≥380px）：①状态区（双水温仪表盘 canvas + 体温 30min 曲线 Chart.js + TEC/风扇/模式开关）②参数区（**按 registry 动态渲染滑条+步进器，仅 flags&PF_WEB**）③高级区（折叠面板，M207 参数——registry 里出现即自动生成，零页面改动）④报警横幅+急停。深色主题；断连灰罩+重连倒计时；多次重连失败提示「请靠近设备」。

### 4.4 OTA 预留

分区表（16MB）：nvs(24K)+otadata(8K)+**ota_0(3M)+ota_1(3M)**+www(512K)+剩余 user。首期只做 esp_ota 写入接口自测（网页上传 UI 二期）；分区表现在定死，**避免日后改分区表引发全片重烧**。

### 6.2 alarm_bits 位定义（u16）

bit0 ALM_BODY_SENSOR / bit1 ALM_M207 / bit2 ALM_ESTOP / bit3 ALM_OVERTEMP(tc1_act>48°C 硬阈值) / bit4 ALM_EEPROM / bit5-15 保留。任一位置位→顶栏红横幅+网页横幅；清除路径：报警源恢复+人工确认（0x15 cmd=9 或屏按钮）。

## 11. 结果保障执行包（v2.1 新增）

### 11.1 为什么这次结果会好（对"上次不满意"的机制性回应）

上次类项目（墨水屏）失败根因复盘：①硬件边界未先证实就写软件 ②"编译过=完成"无运行时证据 ③步子太大一次集成。本任务书的对应机制：
1. **硬件先行证实**：M0 引脚审计已完成（非猜测）、CubeMX 复核是 WP0 前置、每个外设模块上板前先有模拟器/单测。
2. **DoD 强制运行时证据**：每个 WP 的完成定义是"日志行/截图/实测数据"，不是"代码写完了"。
3. **垂直切片 ≤ 半天/WP**：每个 WP 结束都有可见可验收的东西，绝不积累两周再大爆炸集成。
4. **每个 WP 完成即请你 1 分钟验收**（看屏幕/看串口一行），不满意当场返工，成本最低。

### 11.2 M207 模拟器（tools/m207_sim.py）

PC 端 pyserial：应答 `TCACTTEMP?`（返回按正弦缓变的模拟水温）、记录收到的 `TCADJTEMP/TCSW` 并打印。**用途：M207 实物接线前，WP4 全流程（协议→屏幕→调参→报警）先行完成并验收**；实物到位只做替换验证。TMP117 无模拟器（I2C 直连，用 PC 单测+短接实验替代）。

### 11.3 答辩演示脚本（8 分钟，M4 后即可彩排）

①开机 15s 内屏幕亮起显示双水温（水温用手搓温度计或热水杯制造变化）→ ②触摸调 tc1_set +0.5，M207 面板/回读同步 → ③切自动模式，手握 TMP117 使体温超 37.7，屏幕自动进制冷+风扇开 → ④手机连 TCS-XXXX 热点打开网页，网页改参数屏幕 1s 内同步 → ⑤拔 TMP117：屏幕+网页同时红横幅报警、TEC 自动停、风扇全开 → ⑥网页点急停演示。每个动作对应日志 grep 行可复核。

### 11.4 过程纪律

每日收工前：git commit（含证据文件）；任何 WP 卡住 >2 轮迭代→停下按 embedded-dev-loop §4 格式报告；范围蔓延（想加的功能）→ 记入「二期清单」不进本期。
