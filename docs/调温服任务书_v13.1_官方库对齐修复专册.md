## §2 W1 ft5446 软件 I2C → ST HAL I2C4（深化版）

### 2.1 现状与目标映射（逐函数）
| 现函数（ft5446.c） | 官方替换 | 备注 |
|---|---|---|
| ct_iic_init/start/stop/wait_ack/send_byte/read_byte/delay（7 个，~L141-260） | **全删** | 时序由硬件 I2C 外设接管 |
| `ft5446_rd_reg(reg,buf,len)` | `HAL_I2C_Mem_Read(&hi2c4, FT5446_CMD_WR(0x70), reg, I2C_MEMADD_SIZE_8BIT, buf, len, 20)` | 官方 Mem_Read 模式与现序列逐位等价（写 reg→Sr→读）；NAK 计数改为查 HAL 返回值累加 `g_ft5446_nak_cnt`（计数器保留=400k 决策数据源） |
| `ft5446_wr_reg`（init 4 次调用） | `HAL_I2C_Mem_Write` 同构 | 写序列与官方例程一致 |
| FT_RST(PH6)/INT(PH7)/上电延时 | **不动** | 与传输层无关 |
| 上层（touch_session/坐标映射/ftlog/TCS_SIM 注入） | **零改动** | T-13 映射断言原样=回归锚 |

### 2.2 引脚与时钟（每项留档）
1. PD12→I2C4_SCL、PD13→I2C4_SDA，`GPIO_AF4_I2C4`（hal_gpio_ex.h），GPIO_MODE_AF_OD、内部上拉沿用现配置、SPEED_HIGH；
2. **I2C4 kernel clock 选择 + TIMINGR 必须由 CubeMX（官方工具）生成**：在 400k 与 100k 两档、实际选定 kernel 时钟下各生成一次，**计算页截图入 evidence**（这是官方数值的唯一合法来源，禁止手算照抄网络值）；
3. HAL_I2C_MspInit 新增 I2C4 分支（现工程无 hi2c4；与 I2C1/TMP117 共存核对 RCC/中断优先级）；
4. `FT5446_I2C_FAST` 编译宏切 400k/100k；`FT5446_BITBANG` 宏保留旧实现一个版本期。

### 2.3 时序账（诚实数字；实测后以 T-12 数据覆盖）
- bit-bang 现速 ≈200-250kHz（ct_iic_delay=2µs 半周期+GPIO 翻转开销）：
  空闲轮询 47bit ≈ **188-235µs**；触摸轮询 ~101bit ≈ **404-505µs**；
- HAL@400k：空闲 ≈ **117µs**；触摸 ≈ **253µs** → **标称收益 1.6-2.0×**；
- **真实收益大头=时序确定性**：bit-bang 周期依赖 delay 循环，在主循环负载下有抖动（WP-M 调度饥饿假设的温床）；硬件 I2C 时序与负载解耦。结果文档必须同时给"平均"与"最坏"两组数。
- **WCET 约束**：HAL 轮询模式单次阻塞 ≤250µs 级；触摸轮询在 10ms 节拍内的占用重测入预算表（v11.3 第八章 touch 行）；禁止在中断上下文调用。

### 2.5 实施拆分（每步有产物）
- **W1a 配置编译**：hi2c4+MspInit+宏双档+CubeMX TIMINGR 截图；产物=零警告编译+map 体积对比。【L1】

## §3 W2 websocket 上行 JSON 统一 cJSON（深化版）

### 3.1 逐点位改造表（6 处实测行号）
| 行 | 现状 | cJSON 化 |
|---|---|---|
| L84 | st invalid 一行 | CreateObject+AddString(t)+PrintBuffered+Delete |
| L87 | st 全量（14 字段） | 同上，字段逐一 Add |
| L107/112/119 | reg 三段 o+= 拼装 | 整体 cJSON 构造（数组）一次成型 |
| L126 | push_pv | 同 L84 模式 |

### 3.2 深水区一：堆策略（v13.0 缺失的整块分析）
- **500ms 周期推送禁止无界 malloc**：`cJSON_PrintUnformatted` 每次堆分配→72h 浸泡的碎片风险。对策=**官方 API `cJSON_PrintBuffered(tree, cap, 0)`**：预检缓冲不足才扩——st 帧定 cap=256B、pv cap=128B（按字段最大宽实测定，留档计算）；打印后必 `cJSON_Delete`。
- **reg 帧（50 参≈6-8KB）**：变更频率低→**缓存复用**：registry 版本号变化才重建字符串（官方模式"immutable 大对象缓存"）；重建期间加锁。
- heap 高水位对照进 E-19 浸泡指标（改前/改后两组）。

### 3.3 深水区二：线程安全（v13.0 缺失的整块分析）
- cJSON 非线程安全。实施第一步=**调用上下文枚举表**：`grep -n "ws_status_json\|ws_registry_json\|push_pv" esp32/ --include=*.c -r`，逐调用点标注任务（ws 推送任务/httpd 工作线程/其他）；
- 若确认多线程并发（预期：httpd api 线程+ws 推送任务都会调 ws_status_json）→ 包一层 FreeRTOS 互斥（官方 `xSemaphoreCreateMutex`）；或每调用栈上构造+打印加锁最小窗口（选择后者：锁只包 PrintBuffered+memcpy）。
- 转义测试向量（L1 单测，逐条）：字段值含 `"`、`\`、控制字符、UTF-8 中文（50 参最长名实测串）、超长数值（tc1=-10.0/100.0 极值）。
- 回归：CDP 24+改前后 JSON 语义等价 diff（web_mock 复用）+真机 WS 抓帧（L3）+E-02/E-17×5。

## §4 W3 comm txq 官方化·两阶段（深化版）

### 4.1 阶段 A 交付物（评估文档 docs/results/W3_txq_评估.md）
1. **生产者/消费者枚举表**（本册已初测，执行者复跑补全）：`grep -rn "comm_send\|comm_txq_push\|comm_poll_tx" esp32 project_tcs --include=*.c`——H743：主循环单线程（comm_tick 已在主循环，非 ISR，main.c:608 实证）；ESP32：link 任务收敛（tcs_snap 无直调，实证）；**每个调用点一行：文件/行/任务上下文/是否 ISR**；
2. **六操作语义映射表**（含差异项的官方等价实现）：
   | txq 操作 | 官方（FreeRTOS） | 差异与对策 |
   |---|---|---|
   | push | xMessageBufferSend（常规通道） | 项定界=本帧带长度前缀（官方项语义） |
   | **push_front（急停队头插队）** | **无官方等价**→高优先 MessageBuffer 独立通道 | 消费端先高后低（官方优先级队列设计模式） |
   | poll_tx | 先高后低 xMessageBufferReceive | 一次一发语义保持 |
   | count | xMessageBufferSpacesAvailable 反算 | 调试口径换算说明 |
   | **满丢老** | **MessageBuffer 满=Send 失败，不丢老** | 外层判断：满→先 Receive 丢一帧再 Send（保持丢老语义，官方组合模式） |
   | 临界区钩子 | FreeRTOS 内建线程安全（单产单消） | **若枚举表证实多生产者→必须外互斥**，此时评估结论倾向 NO-GO（复杂度反超） |
3. **Q5 保护策略**：comm.c 双端同文件同步改：可移植缺省实现=现环形（H743/PC；文件头查证记录注释："CMSIS/HAL 无官方队列原语，检索日期…"）+ ESP32 init 注入官方后端（函数表，静态创建 `xMessageBufferCreateStatic` 防堆碎片，高 1KB+常规 4KB 对照现 16×253B 静态占用量）；md5 门禁保持。
4. **NO-GO 量化判据**（任一命中即不换，留档结案）：急停 E-04 时序劣化 >10%；等价性金测（同输入帧序列→双后端消费序逐帧一致）不过；注入层使 PC 单测不可跑。

### 4.2 阶段 B（GO 才做）：实现+**双后端等价性金测**（PC 单测新增：同一帧序列喂缺省/官方后端，消费顺序逐帧比对）+LPBK4+ARQ 单测+双板 E-04（P-3 慢动作实测）/E-09/E-10+E-19 浸泡窗口水位。
