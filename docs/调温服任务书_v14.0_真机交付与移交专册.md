## §1b 质量下限令 I：关单双人制（红队证伪协议）——关单不再一人说了算

### 1b.1 双签制
每个 W 关单需要**两份文档**（模板附录 A/B），缺一无效：
- **制方完成报告**（执行者，附录 A 填空式）；

### 1b.2 红队职责（对称反偷懒）
1. **逐 DoD 证伪**：对完成报告每条 DoD 亲手复跑证据或读代码求反例——只写"我做了什么破坏尝试、结果如何"，禁止"看起来没问题"；
2. **发现 ≥3**（重大=功能/安全/官方性违背；一般=预算超/证据缺/工艺违例；微瑕=H17 级）：坐实→must-fix（清零前不放行）或 wont-fix（理由留台账）；
3. **红队零发现且证伪记录 <3 条=评审无效重做**——没找到问题只说明没认真破坏（与找崽条款同源，但角色独立、利益对立）；
4. 最差执行者测试（§1b.5）与工艺门槛（§1d）由红队执行并记录。

### 2.3 时序账（诚实数字；实测后以 T-12 数据覆盖）
- bit-bang 现速 ≈200-250kHz（ct_iic_delay=2µs 半周期+GPIO 翻转开销）：
  空闲轮询 47bit ≈ **188-235µs**；触摸轮询 ~101bit ≈ **404-505µs**；
- HAL@400k：空闲 ≈ **117µs**；触摸 ≈ **253µs** → **标称收益 1.6-2.0×**；
- **真实收益大头=时序确定性**：bit-bang 周期依赖 delay 循环，在主循环负载下有抖动（WP-M 调度饥饿假设的温床）；硬件 I2C 时序与负载解耦。结果文档必须同时给"平均"与"最坏"两组数。
- **WCET 约束**：HAL 轮询模式单次阻塞 ≤250µs 级；触摸轮询在 10ms 节拍内的占用重测入预算表（v11.3 第八章 touch 行）；禁止在中断上下文调用。

## §14 卡点与阻塞（只描述客观问题，不含解决方案）

**K-01 网页链路不可自测**
ESP32 侧仅 SoftAP（SSID `TCS-A8A1`，192.168.4.1），无 STA 上行。开发机主网卡承载公网与模型连接（10.236.x → 公网），连入该 AP 即失去外网。现场无第二台可用终端。

**K-02 触摸物理层未被覆盖**
`tap`/`drag` 把样本注入 `ts_feed()` 同一状态机，但注入样本 `injected=1` 会豁免幽灵会话判定（`touch_session.h` 注释明示），且不经过 FT5446 采样、坐标映射、面积/压感字段。真实面板行为与注入路径在这一层不等价。

**K-03 TMP117 缺位造成的连锁**
I2C0 上电即 NACK（实测日志 `body=0.00(ok=0)`）。后果：`ALM_BODY_SENSOR` 常置 → `post_arm_state()=LOST_ALARM`；`safe_sources_recovered()` 恒 false → 自动模式实际进入 SAFE（已观测 `fan=100%`、`state=3`）。任何"自动闭环"相关验收在当前硬件上不可执行。

**K-04 风扇无反馈通道**
未装风扇，只有 GPIO42 的 PWM 波形可测；转速、堵转、噪声无观测手段。

**K-05 无热负载**
M207 的水温由环境温度决定，无法构造升温/降温阶跃；闭环、超调、过温保护、超温二次确认的实际效果只能验"配置写入 + 寄存器回读"，不能验物理响应。

**K-06 两条调试通道互相干扰**
- ESP32：每次 `pyserial` 打开 COM3 都会因 DTR/RTS 复位芯片（本会话反复出现计数归零、日志中断）；须 `s.dtr=False; s.rts=False` 且一次打开全程复用。
- H743：`probe-rs` 每次访问暂停内核约 1 s，IWDG 窗口 2 s，连续操作有复位清日志风险；H743 控制台另有 COM18（USART1，115200）可绕开该限制。
- 两侧同时高频采样的取证方式因此受限。

**K-07 F17 未定位**
历史记录：H743 控制台命令触发 HardFault，CFSR=0x00000401（ICCAVIOL）。本轮数十次控制台命令（含 tap/drag/pindrv/wave/txwave）未复现；触发条件、与混合工作区构建或探针暂停的相关性均未证实。

**K-08 注册表 `commissioned` 两端不一致**
H743 EEPROM 值 = 1，ESP32 NVS = 2；快照载荷不含该字段，屏幕侧该值不参与控制。两侧语义归属未定。

**K-09 未知 WS 客户端**
本会话观测到持续下发 `{"t":"set","id":1,"v":30.5}` 与 0x13 连发（曾把 23 KB/s 链路打满一次）。开发机 `netstat` 无到 192.168.4.1 的连接。网页写路径已改为本端权威，但该客户端宿主未定位。

**K-10 0x13/0x14 全量握手未验证**
本轮 H743 侧 `getreg` 计数为 0（无请求发生）；50 条注册表经 0x14 下发的完整性与去重未取证。

**K-11 终审腿三未完成**

### 15.7 已知工具坑（会直接造成误判）
1. 用 pyserial 打开 ESP32 COM3 → 芯片复位、计数归零、日志断流（本会话多次误判为"链路断开"）。
2. `probe-rs read` 每次暂停内核约 1 s；连续多次会触发 IWDG（2 s）复位。
3. bash heredoc 会吞反斜杠：用 heredoc 写 C 代码中的 `\n` 会变成真换行并导致编译失败——改代码应使用 Edit 工具。
4. H743 RTT 上缓冲仅 1024 B；控制台 TX 环 2048 B（已修为分块发送，但一次性大输出仍建议分段）。
5. `p list` 在缺陷 #13 修复前只能打印 7~18 行；在旧固件上比对注册表会误以为"参数缺失"。
