# 调温服网页控制台 — WS / HTTP 契约

> 固件（`esp32/components/tcs_web/`）与前端（`web_files/`）之间**唯一**的接口依据。
> 改任何一条消息：同 commit 改 `websocket.c` / `web_status.c`、`web_files/app.js`、`tools/web_mock.py`、
> `tests/test_web_status.c`（主机契约测试），并更新本文件。
> 版本：v2（2026-11-24，U 线）。v1（状态取屏幕回传 0x10）已废止。

## 1. 端点

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/` , `/index.html` | 页面（gzip 内嵌） |
| GET | `/style.css` , `/app.js` , `/chart.js` | 样式 / 应用逻辑 / 自绘曲线（gzip 内嵌） |
| GET | `/api/status` | 当前状态， body = 一条 `st`（见 §2.1） |
| GET | `/api/registry` | 注册表， body = 一条 `reg` |
| GET | `/api/log` | 事件日志全量（最近 50 条）， body = 一条 `log` |
| GET | `/api/linkstats` | 屏链路收发计数 + 热点凭据， body = 一条 `link`（见 §2.7） |
| WS | `/ws` | 文本帧，每帧一条 JSON 对象 |

所有 JSON 为 UTF-8，数字为有限值；温度单位 °C。
静态资源带 `Cache-Control: no-cache`、接口带 `no-store`（固件升级后浏览器不会沿用旧脚本）。
WS 会话：服务端自己应答 PING/CLOSE；**只接受完整的文本帧**——二进制帧、分片帧、≥128 字节的帧
一律关闭连接（不留半条）。不带 `Upgrade` 头的普通 `GET /ws` 回 HTTP 400。
并发 WS 客户端上限 4（`WS_MAX_CLIENTS`）：第 5 个收到 `{"t":"err","code":"server_busy",…}` 后被关闭。

## 2. 服务端 → 客户端

### 2.1 `st` 状态（周期 500ms；业务字段变化时立即追加一帧）

"变化"按**发出去的值**判断（水温/体温取两位小数）：`age`、`up_s`、`ts`、`heap` 的起伏不算变化——
它们本来就在走，算进去等于每拍都"变了"，500ms 心跳就永远走不到（真机上曾是约 10Hz）。

```json
{"t":"st","seq":41,"ts":14815234,"ver":1,"fw":"1.2.0",
 "tc1":18.47,"tc2":21.51,"body":37.40,"age":1000,
 "tc1_set":5.0,"tc2_set":26.0,
 "tec1":0,"tec2":0,"fan":0,"mode":0,"state":0,
 "alarm":0,"latch":0,"armed":1,
 "m207":1,"body_ok":1,"sens_open":0,"screen":1,
 "up_s":14815,"reset":11,"heap":8519084}
```

| 字段 | 类型 | 含义 |
|---|---|---|
| `seq` | int | 推送序号，每帧 +1（仅用于判丢帧/乱序） |
| `ts` | int | 设备开机以来的毫秒数（事件日志与曲线的时间轴基准） |
| `ver` | int | 屏间协议版本 `TCS_PROTO_VER`（目前 1） |
| `fw` | string | ESP32 应用固件版本 |
| `tc1` `tc2` | number | 贴身 / 环境水箱实际水温（M207 回读；离线时为最后一次有效值，配合 `m207`/`age` 判断是否可信） |
| `body` | number | 体温（滑动均值；`body_ok=0` 时为最后一次有效值） |
| `age` | int | 两路水温中较旧一路距上次有效采样的毫秒数；`65535` = 未知/离线 |
| `tc1_set` `tc2_set` | number | 两路设定温度 |
| `tec1` `tec2` `fan` | 0/1 | 执行器开关状态（`fan=1` 含安全态全速） |
| `mode` | 0/1 | 0 手动 / 1 自动 |
| `state` | 0/1/2/3 | 控制状态机：0 待机 / 1 制冷 / 2 制热 / 3 安全态 |
| `alarm` | bitmask | 见 §3.1 |
| `latch` | bitmask | 安全锁存（掉电保持），见 §3.2；非零即处于安全态或等待人工解除 |
| `armed` | 0/1/2 | 布防：0 未布防 / 1 已布防 / 2 布防但源丢失报警中 |
| `m207` `body_ok` `sens_open` | 0/1 | 温控模块在线 / 体温传感器有效 / 水温探头断线 |
| `screen` | 0/1 | 屏幕链路是否存活（屏幕断连时网页照常工作） |
| `up_s` | int | 开机秒数 |
| `reset` | int | 本次开机复位原因（`esp_reset_reason_t` 原始值：1 上电 3 软件复位 4 panic 5 中断看门狗 6 任务看门狗 9 欠压 …） |
| `heap` | int | 空闲堆字节数 |

### 2.2 `pv` 参数变更（任一来源改参后推送；网页自己发起的 `set` 必回一帧带 `ref` 的 `pv`）

```json
{"t":"pv","id":1,"v":30.5,"src":"web","clamped":0,"ref":17,"ok":1,"err":0}
```

| 字段 | 含义 |
|---|---|
| `id` `v` | 参数 id 与**实际生效值**（被限幅时为限幅后的值） |
| `src` | `"web"` 网页 / `"screen"` 屏幕触摸 / `"console"` 控制台 / `"system"` 内部 |
| `clamped` | 1 = 请求值超出范围，已限幅 |
| `ref` | 回显客户端 `set.ref`。**带 `ref` 的那一帧只发给请求者**；别的在线客户端收到同一事件的 `ref=0` 副本（各页面的 `ref` 都从 1 数起，群发会撞号）。非网页来源时恒为 `0` |
| `ok` `err` | `ok=1` 成功；`ok=0` 时 `err` = `param_set` 返回码：`-1` 未知 id / 只读；`-2` 被拒绝——值非有限（NaN/Inf）、跨参数约束（过冷阈值 ≥ 过热阈值）、**急停或超温锁存期间切自动** |

**每个 `set` 必有且只有一帧带其 `ref` 的 `pv`**，包括"值没变"和"被拒绝"两种情况。
客户端认领回执时同时核对 `id`：`ref` 相同但 `id` 不同的一律不是自己的。

### 2.3 `ack` 命令回执

```json
{"t":"ack","c":8,"rv":0,"ref":18}
```

`rv`：`0` 成功；`-1` 未知命令；`-2` 被拒绝——TEC/风扇类命令在 `state=3` 时，或**急停/超温锁存期间切自动**（命令 6）；
命令 `10`（保存到模块）时 `rv` = 已下发给模块的条数（不是"模块已存好"的确认），`-2` = 模块离线未保存。

`ack` **只发给发起这条命令的客户端**（别的页面不会收到不属于自己的 `ref`）。命令 `9`（解除/确认）的 `rv` 恒为 `0`；
是否真的解除要以之后的 `st.alarm` / `st.latch` 为准（急停要等其余故障都恢复才能解除）。

### 2.4 `reg` 注册表（连接建立时推一次；之后由 `pv` 增量更新，不再整表重推）

```json
{"t":"reg","list":[{"id":1,"type":0,"flags":31,"min":5,"max":45,"step":0.1,"def":5.0,
                   "key":"tc1_set","name":"贴身水箱设定温度","unit":"°C"}]}
```

`type`：0 浮点 / 1 u8 / 2 u16 / 3 动作项。`flags` 位：`0x01` 可写 `0x02` 屏上可见 `0x04` 网页可见
`0x08` 本机持久 `0x10` 需下发模块 `0x20` 保护/限幅类（改动需二次确认）。`def` = **当前值**（字段名沿用 v1）。
客户端收到 `pv` 后应更新本地注册表里对应条目的 `def`（整表约 7KB，不在每次改参时重推）。
数值一律写成**最短且能还原成同一个 float32 的十进制**（`web_num_short`）：参数表里是 `float`，
直接按 double 打印会带出 `0.10000000149011612` 这样的尾数，页面按它数小数位就会变成 17 位。

### 2.5 `log` 事件日志

```json
{"t":"log","list":[{"ts":14812000,"lvl":"alarm","ev":"estop_on","msg":"急停触发"}]}
```

`lvl`：`info` / `warn` / `alarm`。连接建立后先推全量历史（≤50 条），之后只推新增事件（每帧 1..N 条）；
全量已经覆盖了连接之前积压的事件，所以同一事件不会既在全量里、又在增量里再出现一次。
事件码表见 `web_status.c` 的 `web_status_diff_log`（`estop_on/off`、`overtemp_on/off`、`safe_in/out`、
`body_lost/body_ok`、`m207_offline/m207_online`、`sens_open/sens_closed`、`screen_down/screen_up`、
`mode`、`tec1_on/off`、`tec2_on/off`、`fan_on/off`、`param`、`ws_open`、`m207_save`、`boot`）。
`ws_open`（网页已连接）30s 内连续重连只记第一条；断开不记。

### 2.6 其它

- `{"t":"pong","ts":<ms>,"ref":<ref>}`：应答 `ping`（客户端测链路延迟与存活），带回 `ping.ref`。
- `{"t":"err","code":"…","msg":"…"}`：`bad_json`（JSON 语法错/非对象/缺 `t`）、`bad_set`（`id`/`v` 缺失或
  `id` 不是 1..65535 的整数）、`bad_cmd`（`c` 不是 1..10 的整数）、`unknown_type`、`server_busy`。

### 2.7 `/api/linkstats` → 一条 `link`

```json
{"t":"link","rx_bytes":769101,"rx_frames":29665,"crc_err":40,"len_err":0,"gap_resets":0,"dup":1,"retry":77,
 "txq_drop":3,"uart_txdrop":0,"echo_drop":0,"pending_evict":0,"proto_mismatch":0,
 "ssid":"TCS-9A3C","pass":"12345678","url":"http://192.168.4.1"}
```

屏幕↔主控链路的收发计数（诊断接线接触不良：`crc_err` / `echo_drop` 持续增长）+ 当前生效的热点凭据与网址。
这些量不常变，不进 `st`；前端在"设备"页打开时取、之后每 5s 刷新一次。

## 3. 位定义（与 `protocol/tcs_proto.h`、`tcs_core/control.h` 同源）

### 3.1 `alarm`

| 位 | 值 | 含义 | 退出方式 |
|---|---|---|---|
| 0 | 1 | 体温传感器失联 | 源恢复后 2s **自动** |
| 1 | 2 | 温控模块通信失联 | 源恢复后 2s **自动** |
| 2 | 4 | 急停 | **仅人工解除** |
| 3 | 8 | 水温过高（>48°C） | **仅人工解除**，且水温须已回落 |
| 4 | 16 | 参数存储校验失败（提示性） | 人工确认 |
| 5 | 32 | 水温探头断线 | 源恢复后 2s **自动** |

### 3.2 `latch`

| 位 | 值 |
|---|---|
| 0 | 1 超温锁存 |
| 1 | 2 体温传感器丢失锁存 |
| 2 | 4 温控模块/探头丢失锁存 |
| 3 | 8 急停锁存 |

## 4. 客户端 → 服务端

```json
{"t":"set","id":1,"v":30.5,"ref":17}
{"t":"cmd","c":8,"ref":18}
{"t":"ping"}
```

`ref`：客户端自增整数（0..2^32-1），服务端在对应的 `pv` / `ack` 里原样带回。缺省为 0。
`id`、`c`、`ref` 必须是整数：带小数或超范围的帧回 `bad_set` / `bad_cmd`（不做截断——65537 不会被当成 1）。

### 4.1 命令码（网页只放行 1..10；其余一律 `bad_cmd`）

| c | 含义 | 说明 |
|---|---|---|
| 1 / 2 | 贴身水箱 TEC 开 / 关 | 安全态下拒绝（-2） |
| 3 / 4 | 环境水箱 TEC 开 / 关 | 同上 |
| 5 | 风扇 切换 | 同上 |
| 6 / 7 | 切自动 / 切手动 | 自动模式按体温闭环控制贴身水箱。**急停或超温锁存期间切自动被拒绝（-2）**：急停复位后不得自动重启，解除后要再明确切一次 |
| 8 | **急停** | TEC 全关 + 风扇全速 + 切手动 + 锁存（掉电保持） |
| 9 | **确认 / 解除** | 清除"源已恢复"的报警；急停只有在其余源全部健康时才解除 |
| 10 | 保存高级参数到模块 | 模块 EEPROM，掉电保持 |

### 4.2 常用参数 id

| id | key | 名称 | 范围 / 步进 | 备注 |
|---|---|---|---|---|
| 1 | `tc1_set` | 贴身水箱设定温度 | 5–45 / 0.1 °C | 超过 id 7 阈值需二次确认 |
| 2 | `tc2_set` | 环境水箱设定温度 | 5–45 / 0.1 °C | 同上 |
| 3 | `body_hot` | 体温过热阈值 | 36–40 / 0.1 °C | 必须大于 id 4 |
| 4 | `body_cold` | 体温过冷阈值 | 35–39 / 0.1 °C | 必须小于 id 3 |
| 5 | `hyst` | 滞回回差 | 0.1–1.0 / 0.1 °C | |
| 6 | `mode` | 控制模式 | 0 / 1 | 手动 / 自动 |
| 7 | `tc_set_confirm` | 高温二次确认阈值 | 38–45 / 0.5 °C | |
| 8 | `commissioned` | 布防模式 | 0 / 1 / 2 | 自动 / 强制布防 / 强制不布防；`flags` 含 0x20 |
| 0x100–0x126 | `m207_*` | 模块高级参数（PID / 保护 / 输出限制 / 系统） | 见 `reg` | 保护类 `flags` 含 0x20 |
| 0x130–0x135 | `m207_*_st` 等 | 只读遥测 | — | 无 `0x01` 位，不出编辑控件 |

## 5. 时序约定

- 服务端 `st` 周期 500ms；业务字段变化后 ≤100ms 追加推送。
- 客户端：超过 2s 未收到 `st` → 标"数据过期"（数值变灰，不可当作实时值）。
- 客户端：WS 关闭，或**任何帧都收不到超过 10s**（Wi-Fi 静默断开不会触发 close）→ 连接视为断开：
  遮罩 + 指数退避重连（1,2,4,8,10s 封顶）。同一时刻只保持一条连接（重试按钮在连接中不可点）。
- 客户端：`set` 1.5s 内没有收到同 `ref` 且同 `id` 的 `pv`、`cmd` 1.5s 内没有收到同 `ref` 的 `ack` → 按"未确认"提示（不自动重发，避免重复写）。
- 客户端每 5s 发一次 `ping` 测往返延迟。
